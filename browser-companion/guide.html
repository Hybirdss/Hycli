Your browser, already signed in.

The browser companion connects the account you use on a website to Hycli. Your browser sends its sign-in cookies directly to the local credential vault. AI models receive only the account label and the tools they can use.

Try automatic sign-in discovery first

Website preparation checks your existing browser profiles automatically. You can repeat this from Accounts → Connect an account → Find my sign-in. If it cannot read the session, choose Open website sign-in. Keep the dialog open while signing in; Hycli rechecks and resumes only when your account is verified.

Native import respects OS protection. Windows App-Bound cookies, browser-only tokens, live session state and separate private or container contexts may require a supported browser connection or documented API credential.

Install the companion

  1. Download the browser companion from Accounts → Connect an account, then unzip it into a folder you will keep.
  2. In Chrome, open chrome://extensions. In Edge, open edge://extensions.
  3. Turn on Developer mode, choose Load unpacked, and select the extracted folder.
  4. Pin the Hycli companion beside your address bar.

The companion is distributed as local source in this release. It is not published in a browser extension store. Chrome and Edge use the first download. For Firefox, download the Firefox package, unzip it, open about:debugging#/runtime/this-firefox, choose Load Temporary Add-on, and select its manifest.json. Firefox removes temporary add-ons when it restarts; signed store distribution is not included in this release.

Connect a website

  1. Sign in to the website in your browser.
  2. In Hycli, open Accounts → Connect an account, choose the website and create a connection code.
  3. Open the Hycli companion, enter the code, and continue. If you changed the dashboard port, expand Dashboard address and use the address printed by Hycli.
  4. Choose Connect this account and allow access to that website. The code expires in five minutes and can connect only one account.
Account names come from the website.

Hycli never treats your browser profile name as a verified website identity. If no current-account response has been observed, the dashboard says the account is unidentified. After granting permission, use the website's account/profile page normally, and the companion can pass the observed account URL automatically for seven days after connecting. Hycli checks that response locally.

Privacy and browser profiles

Connect from the browser profile containing the desired login. Cookies are scoped to the exact website origin and stay inside the local executor. The extension records only candidate current-account URLs, never response bodies or authentication headers. A website using a separate bearer-token login may need a documented API credential instead of cookies.

For a private window, enable the extension in private browsing and connect from that window. Disconnecting in Hycli removes its saved credentials; it does not sign you out of the website.

If the website asks you to sign in again

Sign in normally in the browser and reconnect. Hycli pauses when a site asks for authentication, presents a challenge or limits requests. It does not bypass challenges or rotate identities. No tool can promise that a site will never restrict an account.
