<a id="get-started"></a>
Введіть домен і за бажанням вкажіть мету поруч. Спочатку ШІ вивчає сайт і вибирає корисні завдання, потім перевіряє передумови, дані та результати. Якщо бракує кроків, сайт залишається позначеним для перевірки.

## Початок роботи

**[Завантажити v0.1.0 · Linux x64](https://github.com/Hybirdss/Hycli/releases/tag/v0.1.0)** · glibc ≥ 2.39 · [SHA-256](https://github.com/Hybirdss/Hycli/releases/download/v0.1.0/hycli-0.1.0-linux-x64.tar.gz.sha256)

Hycli — застосунок на Rust із локальною вебпанеллю. У цій копії репозиторію зберіть панель і виконуваний файл:

```sh
node scripts/build.mjs
./dist/hycli dashboard
```

Панель відкривається за адресою `http://127.0.0.1:4318`. Команда `hycli dashboard --no-open` виводить адресу без відкриття браузера. Параметр `--port 4320` дає змогу вибрати інший порт. Рушій сайтів і панель входять до одного виконуваного файлу.

1. Відкрийте **Підключення ШІ** та підключіть постачальника.
2. Додайте адресу сайту й виберіть ШІ для його підготовки.
3. Перегляньте доступні дії. Запустіть одну з них на панелі або відкрийте **Агенти для програмування**, щоб один раз скопіювати конфігурацію MCP.

Якщо на сайті потрібен вхід, підключіть обліковий запис у розділі **Облікові записи**. Для одного сайту можна зберегти кілька облікових записів і вибрати той, який використовуватимуть його інструменти.

<a id="what-your-ai-can-do"></a>
## Що може ваш ШІ

Hycli перетворює підтримувані операції сайту на інструменти з назвами й визначеними типами даних. Описи, написані ШІ, пояснюють, що робить кожна дія, які відомості їй потрібні та що вона повертає.

Три незалежні агенти ШІ займаються читанням і пошуком, корисними сценаріями роботи та відомостями про обліковий запис. Панель показує завершені етапи, стан кожного агента, час роботи й зрозумілі нотатки. Дії CLI та MCP відображаються в тій самій історії активності.

  <img src="../../docs/images/preparation.gif" alt="Троє воркерів. Одна дуже заклопотана маленька пташка." width="100%" />
</p>
<p align="center"><sub>Троє воркерів. Одна дуже заклопотана маленька пташка.</sub></p>

Підготовка спирається на відомості, справді доступні на сайті: документацію за посиланнями, схеми API, опублікований JavaScript і структури запитів, які спостерігає розширення браузера. Після запланованих робочих процесів виконавці продовжують працювати над кожною задокументованою операцією API, для якої ще немає дії, доки кожну не буде реалізовано або повідомлено про неї з причиною; поле `coverage` завдання перелічує те, що залишилося. Для перевірки операції можуть виконуватися обмежені запити на читання. Під час підготовки не створюються тестові записи, не редагується вміст, не видаляються об’єкти, не вгадуються великі списки адрес API й не надсилаються випадкові тестові дані на робочий сервер.

| Дія | Поведінка |
| --- | --- |
| Читання або пошук | Виконується самостійно, якщо операцію підтверджено наявними даними та класифіковано як читання. |
| Створення, надсилання, редагування або видалення | Вимкнено, доки ви не дозволите зміни для цього сайту. Після цього показує сайт, обліковий запис, дію та остаточні вхідні дані для вашого схвалення. |
| Незрозумілий наслідок | Потребує перевірки перед надсиланням запиту. |
| Автентифікація, додаткова перевірка або ліміт запитів | Призупиняє відповідні запити й дає змогу підключитися знову або зачекати. |

Кожен сайт починає в режимі «лише читання». Його дії, що змінюють дані, приховано від MCP і відхиляються CLI, доки ви не ввімкнете **Дозволити зміни** у відомостях про цей сайт; повторне вимкнення скасовує схвалення, що очікують. Перемикач і кнопка схвалення є лише в панелі, а панель надає свою сесію тільки адресі, яку відкриває `hycli dashboard`, тому агент, що викликає Hycli, не може ввімкнути зміни чи схвалити власний запит. Агент, здатний виконувати будь-які команди від вашого імені, може також читати ваші файли; залишайте таких агентів під їхніми власними запитами дозволів.

Схвалення стосується одного конкретного запиту, діє п’ять хвилин і може бути використане лише один раз. Зміна вхідних даних, облікового запису, збережених даних входу або встановленого визначення інструмента скасовує його. Це правило однаково діє в CLI, MCP і на панелі. Запити, що змінюють дані, ніколи не повторюються автоматично.

Підтримка залежить від сайту. Сторінці без придатної документації чи спостережуваних операцій може знадобитися браузер із виконаним входом, наданий SiteSpec або додаткова підготовка. Hycli повідомляє, що може підтримати, і не припускає, що кожен сайт має готовий API.

### Підтримувані можливості

Підтримуються OpenAPI у JSON або YAML, REST, GraphQL, JSON-запити й форми з URL-кодуванням. Записи, посилання та наступна сторінка витягуються з HTML за спостереженими селекторами; доступні також GET-сторінки, відтворені локальним Chromium. Якщо читання під час підготовки не вдалося, ШІ аналізує докази, виправляє визначення та перевіряє його знову.

Довільні послідовності кліків, multipart-завантаження та завантаження двійкових файлів поки не реалізовано. Пакети не містять облікових записів або раніше створених CLI.

<a id="use-hycli-with-your-ai"></a>
## Використовуйте Hycli зі своїм ШІ

**Агенти для програмування → Переглянути налаштування підключення**

Загальне підключення MCP дає змогу готувати сайти й виконувати дії. Підключіть агента один раз, щоб він міг створювати відсутні інструменти, відстежувати перебіг роботи й використовувати нові дії.

```sh
hycli mcp
```

Параметр `--sites-only` відкриває лише встановлені дії. Наведене підключення обмежене одним сайтом.

```sh
hycli mcp --sites-only --only-site SITE
```

```json
{
  "mcpServers": {
    "hycli": {
      "command": "hycli",
      "args": [
        "mcp"
      ]
    }
  }
}
```

Якщо `hycli` немає в PATH агента, скористайтеся шляхом до виконуваного файлу з панелі.

Той самий процес доступний у CLI. Замініть приклад URL, `SITE` та `ACTION` своїм сайтом і назвами, які повертає `describe`.

```sh
hycli prepare https://your-website.example --intent "Знайти збережені матеріали"
hycli request SITE "Add draft editing and publishing with full post content"
hycli describe
hycli describe SITE ACTION
hycli SITE ACTION --help
hycli run SITE ACTION --arg query="design systems"
hycli jobs show JOB_ID --watch
```

Перш ніж повторювати невдалу дію, перевірте сайт без ШІ:

```sh
hycli check          # кожен встановлений сайт
hycli check SITE
```

Під час підготовки послідовно записуються успішні читання, зокрема й ті, що передають ідентифікатор попереднього результату наступному. `hycli check` відтворює їх, спершу підтверджуючи особу збереженого облікового запису. Вердикт розрізняє `signed_out` (знову підключіть обліковий запис) і `site_changed` (обліковий запис працює, але відповіді вже не збігаються; попросіть виправлення), а також `blocked` і `unreachable`. Перевірка ніколи не виконує змін, а код завершення відповідає вердикту. Клієнти MCP отримують ту саму перевірку як `hycli_check`.

У MCP передайте URL та `intent` до `hycli_prepare`, а потім стежте за завданням через `hycli_job` або `hycli_result`. `hycli_run` виконує нові дії, навіть якщо клієнт ще не оновив список інструментів. Внутрішні ідентифікатори спершу шукайте через пов’язані дії перегляду списків або пошуку. Інструменти `hycli_result`, `hycli_check` і `hycli_activity` залишаються доступними в обох режимах, щоб ваш ШІ міг стежити за робочими нотатками, перебігом роботи та схваленими результатами й відрізняти вхід, термін дії якого минув від сайту, що змінився.

Дії зі змінами повертають квитанцію для перевірки в панелі. Стежте за її результатом, не повторюючи запит. Невдале читання або неочікувана відповідь також спричиняють помилку CLI.

<a id="browser-sign-in"></a>
## Вхід через браузер

Підготовка сайту починається з перевірки поточної ОС, запущених і зареєстрованих браузерів та доступних профілів. ШІ вибирає з цих можливостей засоби для читання документації, відображення сторінок, імпорту сеансу сайту й перевірки підключення. Шляхи до браузера та профілів залишаються на локальному комп’ютері; створене визначення сайту не залежить від шляхів установлення розробника.

Файли cookie та сховище джерела з Chrome, Chromium, Edge, Brave і Firefox можна імпортувати, якщо вони доступні. До локального сховища Hycli потрапляє лише сеанс запитаного сайту. Hycli автоматично вибирає одну підтверджену особу; профілі цієї особи вважаються одним варіантом під час вибору облікового запису. Наявний вибір облікового запису зберігається; різні підтверджені особи потребують вибору.

У розділі **Облікові записи → Підключити обліковий запис** кнопка **Знайти мій вхід** повторює пошук. Якщо придатного сеансу немає, **Відкрити сторінку входу на сайт** відкриває сайт у браузері за замовчуванням. Поки вікно відкрите, Hycli перевіряє вхід повторно й продовжує підготовку лише після підтвердження вибраного облікового запису. Саме відкриття вкладки не означає успішного входу.

Для сеансів, захищених ОС, прив’язаних до браузера, приватних або ізольованих у контейнері може знадобитися розширення. Виберіть вкладку розширення й створіть код підключення, потім відкрийте розширення в профілі з виконаним входом, введіть код і надайте доступ до сайту. Прямий імпорт не обходить захист Windows App-Bound і не послаблює профіль браузера.

- **Chrome та Edge:** розпакуйте архів і виберіть **Завантажити розпаковане розширення** на сторінці розширень браузера.
- **Firefox:** використовуйте пакет для Firefox і **Завантажити тимчасовий додаток** на сторінці `about:debugging`. Тимчасові розширення видаляються після перезапуску Firefox. Ця версія не включає поширення підписаного розширення через магазин.
- **Файл cookie:** як запасний варіант доступний імпорт файлів cookie у форматах JSON і Netscape. Імпортуйте файл безпосередньо на панелі; не вставляйте його вміст у розмову з ШІ.

Браузер передає дані сеансу безпосередньо до локального сховища облікових даних. Моделі отримують підписи облікових записів, назви й структуру локальних ключів і результати інструментів без значень облікових даних. Вони можуть створити рецепт підключення з посиланнями на ці локальні значення, не отримуючи їх. Враховуються область дії, шляхи, термін дії та підтримувані відомості про розділення файлів cookie; заголовки автентифікації обмежено їхнім початковим джерелом.

Обліковий запис визначається за справжньою відповіддю сайту про поточний обліковий запис. Назва профілю браузера не вважається підтвердженою особою на сайті. Якщо обліковий запис ще не визначено, Hycli повідомляє про це. Після підключення звичайний перегляд сайту може надати відповідь із даними облікового запису та структури доступних запитів. Значення запитів, заголовки й тіла відповідей не розкриваються моделі, що готує інструменти.

Сайту можуть знадобитися окремі задокументовані облікові дані API або функція браузера, недоступна локально. Підготовка записує фактичні результати підключення та читання. Отримання головної сторінки або сторінки входу у відповіді API не означає, що інтеграція готова. [Посібник із налаштування браузера](../../browser-companion/guide.html) описує роботу розширення та обмеження.

## Мови

Панель підтримує 20 мов за посиланнями вище, зокрема арабську з письмом справа наліво. Початкова мова — англійська. Вибір зберігається на цьому пристрої, а описи ШІ можна підготувати вибраною мовою.

<a id="local-data"></a>
## Локальні дані та ліміти запитів

Визначення сайтів, метадані облікових записів та історія залишаються в локальному каталозі даних. Задайте `HYCLI_DATA_DIR`, щоб вибрати інше розташування. У **Налаштуваннях** можна переглянути поточний шлях і спосіб захисту облікових даних.

За наявності системного сховища ключів воно захищає ключ шифрування сховища облікових даних. Якщо системне сховище недоступне, Hycli явно повідомляє, що захист ґрунтується лише на правах доступу до файлів. Приватні каталоги й файли облікових даних доступні лише поточному користувачу ОС. Якщо наявне зашифроване сховище неможливо розблокувати, воно не замінюється непомітно.

Запити виконуються послідовно й із паузами для кожного сайту та облікового запису; додатково діє загальний ліміт сайту. Hycli враховує `Retry-After`, обмежує розміри відповідей і кількість повторів читання, призупиняє роботу за помилок автентифікації чи додаткових перевірок сайту. Під час підготовки сайту Hycli не змінює облікові записи, не підробляє цифрові відбитки й не обходить перевірки; діагностична поведінка рушія може відрізнятися. Ці заходи зменшують зайве навантаження, але не гарантують, що сайт ніколи не обмежить обліковий запис.

Приватні й локальні адреси сайтів за замовчуванням вимкнені. Для довіреного сайту на власному сервері явно запустіть панель або сервер MCP з `--allow-local`.

## Розробка та перевірка

```sh
npm --prefix dashboard ci
npm --prefix dashboard run check
npm --prefix dashboard run build
cargo test --all-targets --locked
cargo build --locked --bin hycli --example dashboard_fixture
node scripts/test-e2e.mjs --full
```

Тести використовують штучні локальні сайти й відповіді постачальників. Вони перевіряють прив’язку схвалення та захист від повторного використання, видалення секретних даних, перенаправлення, ліміти запитів, відсутність повторів запису, захист сеансів браузера й відповідність відповідей постачальників очікуваному формату. Ніколи не створюйте, не змінюйте й не видаляйте вміст у справжньому обліковому записі лише заради перевірки Hycli.

Знімки екрана та GIF використовують ізольовані демонстраційні дані. Див. [джерела зображень](../images/README.md).

## Ліцензія та призначення

Hycli поширюється за ліцензією [Apache-2.0](../../LICENSE).

Hycli призначений для створення й використання інструментів командного рядка, які спрощують роботу із сайтами. Використовуйте його із сайтами та обліковими записами, до яких маєте дозволений доступ.

Програмне забезпечення надається як є, без гарантій. У межах, дозволених законом, автори й учасники проєкту не несуть відповідальності за збитки чи інші проблеми, що виникають через його використання. Ви відповідаєте за те, як користуєтеся програмою.

У межах, дозволених законом, автори та учасники проєкту не несуть відповідальності за блокування, призупинення чи обмеження облікових записів унаслідок використання Hycli. Не використовуйте Hycli для зламу, несанкціонованого доступу чи атак.
