<a id="try-it-in-30-seconds"></a>
## Спробувати за 30 секунд

```sh
# 1. Вкажіть Hycli вебсайт і опишіть мету (готує читання й запис; 0 реальних змін під час підготовки)
hycli prepare https://your-website.example --intent "Шукати публікації, зберігати чернетки та публікувати статті"

# 2. Перегляньте всі підготовлені команди читання, запису та багатокрокові сценарії
hycli describe your-website

# 3. Одразу виконуйте операції читання та пошуку
hycli your-website search-posts --query "примітки до випуску"

# 4. Увімкніть запис один раз для цього CLI, коли будете готові створювати, редагувати чи видаляти
hycli writes your-website allow
hycli your-website create-draft --title "Привіт із Hycli" --body "Автоматизовано просто з термінала."
```

Або підключіть Hycli до **Claude Code, Cursor, Codex чи Windsurf** один раз за допомогою `"command": "hycli", "args": ["mcp"]` і попросіть агента природною мовою:
> *«Використай Hycli, щоб підготувати `https://...`, покажи мені доступні дії та створи чернетку нової публікації».*

<a id="get-started"></a>
## Початок роботи

Hycli постачається як єдиний нативний виконуваний файл, що містить і рушій роботи з вебсайтами, і локальну панель керування (`http://127.0.0.1:4318`). Для запуску релізного пакета не потрібні ні Rust, ні Node.js.

Завантажте нативний інсталятор або портативний архів для вашої платформи зі сторінки **[GitHub Releases (v0.1.0)](https://github.com/Hybirdss/Hycli/releases/tag/v0.1.0)**:

| Платформа | Архітектура | Нативний інсталятор | Портативний архів | Як запустити |
| --- | --- | --- | --- | --- |
| **Windows 10/11** | x64 та ARM64 | `hycli-0.1.0-win32-*-setup.exe` | `hycli-0.1.0-win32-*.tar.gz` | Запустіть `*-setup.exe` (додає `hycli` до користувацького `PATH` і меню «Пуск»), потім відкрийте **Hycli** або виконайте `hycli open` у PowerShell. |
| **macOS 13+** | Apple Silicon (`arm64`) та Intel (`x64`) | `hycli-0.1.0-darwin-*.dmg` | `hycli-0.1.0-darwin-*.tar.gz` | Відкрийте `.dmg`, перетягніть **Hycli.app** у **Applications** і запустіть програму (автоматично зв'язує `hycli` у `~/.local/bin`). |

### Підключіть свій перший вебсайт

1. Виконайте `hycli open` (або натисніть значок програми **Hycli**), щоб відкрити локальну панель керування за адресою `http://127.0.0.1:4318`.
2. Відкрийте **Підключення до ШІ** та підключіть OpenAI, Anthropic Claude, xAI, Z.ai або локальний вхід ChatGPT (Codex).
3. Для сайтів, що потребують входу, натисніть **Облікові записи → Знайти мій вхід**, щоб імпортувати сесію браузера до локального зашифрованого сховища.
4. Введіть URL вебсайту й (необов'язково) мету або скопіюйте конфігурацію MCP з розділу **Агенти програмування** у свого ШІ-помічника.

<a id="what-your-ai-can-do"></a>
## Що може ваш ШІ

Hycli перетворює реальні інтерфейси вебсайтів на самодокументовані підкоманди CLI та інструменти MCP:

| Інтерфейс вебсайту | Підготовлена можливість |
| --- | --- |
| REST та OpenAPI | Типізовані дії читання й запису на основі схем JSON/YAML і документації API. |
| GraphQL | Розібрані документи запитів (`query`) і мутацій (`mutation`) із типізованими JSON-змінними. |
| HTML і сторінки з JS-рендерингом | Структуровані записи, посилання, пагінація та читання GET-сторінок через локальний рушій Chromium. |
| JSON-форми та URL-кодовані форми | Документовані вхідні поля, значення за замовчуванням і надсилання форм у межах облікового запису (`POST`, `PUT`, `PATCH`, `DELETE`). |

| **Читання або пошук** | Виконується негайно, коли підтверджено доказами та класифіковано як безпечне читання. |
| **Створення, надсилання, редагування або видалення** | Виявляється та включається до специфікації CLI без жодного запуску під час підготовки. За замовчуванням вимкнено (`writes: false`). <a id="common-concerns"></a>
## Поширені занепокоєння та як Hycli їх вирішує

Підключення ШІ-агента до реальних вебсайтів і авторизованих облікових записів викликає серйозні запитання. Ось як Hycli вирішує кожне з них на рівні архітектури:

### 1. «Чи не зможе ШІ випадково опублікувати, змінити або видалити дані в моєму обліковому записі?»
- **Жодних реальних змін під час створення CLI:** Під час підготовки чи перевірки вебсайту (`hycli prepare`, `hycli request`, `hycli recon`, `hycli check`) Hycli виявляє та компілює у специфікацію CLI як читання, так і запис, але **ніколи не виконує запити на запис**. Навіть замасковані мутації (`GET`-маршрути зі шляхами змін на кшталт `/delete`, тіла GraphQL `mutation` або надсилання HTML `<form method="post">`) блокуються під час перевірки.
- **Одноразове підтвердження запису для кожного CLI:** Кожен новостворений CLI сайту починає роботу з `writes: false`. Коли ШІ-агенту вперше потрібно виконати дію запису в цьому CLI, він запитує вас **один раз для цього CLI**: *«Дозволити дії запису для `<site>`?»* Лише після вашої згоди він запускає `hycli writes <site> allow` (або MCP `hycli_writes`), відкриваючи пряме виконання запису для цього CLI. Ви можете будь-коли скасувати дозвіл командою `hycli writes <site> deny` або перемикачем **Дозволити зміни** в панелі керування.
- **Жодних автоматичних повторів запису:** Невдалі або перервані запити на запис ніколи не повторюються автоматично. Якщо з'єднання обривається після надсилання мутації, Hycli повертає `action_outcome_unknown`, щоб ви могли перевірити вебсайт, а не створити дублікат замовлення чи допису.

### 2. «Чи надсилає Hycli мої cookie, токени входу або API-ключі до ШІ-моделі?»
- **Секрети ніколи не потрапляють у промпти LLM:** Cookie браузера, токени `localStorage` / `sessionStorage` та API-ключі зберігаються виключно у вашому локальному зашифрованому сховищі (захищеному системною зв'язкою ключів у Диспетчері облікових даних Windows, Ключарні macOS і Linux Secret Service або правами доступу `0600` лише для власника).
- **Символічні рецепти підключення (`ConnectionRecipe`):** ШІ-моделі бачать лише мітки облікових записів, назви ключів сховища та замасковані схеми відповідей. Модель будує символічний `ConnectionRecipe` (посилаючись лише на назву cookie чи токена), а Hycli локально підставляє реальний секрет у момент виконання та очищає секрети з усіх вихідних даних і логів.
- **Імпорт лише для читання в межах одного домену:** Імпорт сесії браузера зчитує cookie та сховище лише цільового домену з тимчасового знімка в режимі читання. Він ніколи не послаблює безпеку браузера та не експортує дані інших сайтів.

### 3. «Чи не призведе збирання даних до появи CAPTCHA або блокування облікового запису?»
- **Жодного фазингу чи перебору ендпоінтів:** Hycli ніколи не вгадує списки URL і не фазить живі сервери. Він навчається лише з пов'язаної документації, схем OpenAPI/GraphQL, статичних JS-бандлів і спостережуваної структури мережевих запитів браузера.
- **Послідовний трафік із контролем темпу:** Запити виконуються послідовно й обмежуються за швидкістю для кожного сайту та облікового запису з дотриманням заголовка `Retry-After` та обмеженням кількості повторів читання.
- **Автоматичний запобіжник стратегій і виконання в контексті реального браузера:** Коли звичайний HTTP-запит натрапляє на код 403/429 або антибот-перевірку (Cloudflare, Akamai Bot Manager), Hycli не зациклює заблокований запит. Запобіжник миттєво перемикає транспорт — виконуючи `window.fetch(..., { credentials: 'include' })` усередині вашого автентифікованого контексту браузера або використовуючи локальний рушій прихованого Chromium — або безпечно призупиняє роботу для захисту вашого облікового запису.

### 4. «Чи може перенаправлення спричинити витік сесії, а спільна специфікація — розкрити шляхи на моєму комп'ютері?»
- **Сувора прив'язка до джерела (Origin):** Заголовки автентифікації та cookie жорстко прив'язані до цільового джерела й негайно видаляються під час міждоменних перенаправлень. Приватні та локальні діапазони IP-адрес за замовчуванням заблоковані, якщо явно не передано прапорець `--allow-local`.
- **Переносні специфікації:** Локальні шляхи до виконуваних файлів і профілів браузерів залишаються лише у внутрішньому стані пристрою та ніколи не записуються до переносних файлів `SiteSpec`.

### 5. «Чи буде ШІ марнувати токени на повторні спроби, коли термін дії мого входу мине?»
- **Детермінована перевірка стану без ШІ (`hycli check`):** Команда `hycli check` (та MCP `hycli_check`) відтворює перевірені ланцюжки читання без виклику LLM і чітко відокремлює `signed_out` (перепідключіть обліковий запис) від `site_changed` (відновіть специфікацію), `blocked` та `unreachable`.

<a id="use-hycli-with-your-ai"></a>
## Використання Hycli з вашим ШІ

Додайте Hycli до вашого MCP-клієнта (**Агенти програмування → Переглянути налаштування підключення** показує точний шлях для вашої ОС):

```json
{
  "mcpServers": {
    "hycli": {
      "command": "hycli",
      "args": ["mcp"]
    }
  }
}
```

Використовуйте `hycli mcp --sites-only`, щоб відкрити доступ лише до встановлених інструментів сайтів, або додайте `--only-site SITE`, щоб обмежити доступ одним сайтом. MCP-сервер надає `hycli_prepare`, `hycli_writes` (вмикає запис один раз для кожного CLI після вашого підтвердження), `hycli_run`, `hycli_check`, `hycli_result` та `hycli_activity` — і ніколи не надає інструмент для читання облікових даних.

Із термінала кожен робочий процес працює так само:

```sh
hycli prepare https://your-website.example --intent "Знайти збережені матеріали"
hycli request SITE "Додай редагування чернеток і публікацію з повним текстом допису"
hycli describe SITE
hycli SITE ACTION --help
hycli writes SITE allow
hycli SITE ACTION --query "design systems"
hycli check SITE
```

<a id="browser-sign-in"></a>
## Вхід через браузер

Hycli виявляє локальні профілі Chrome, Chromium, Edge, Brave, Vivaldi, Arc, Whale та Firefox (а також встановлені локальні бінарні файли прихованого Chromium) у Windows, macOS і Linux, імпортуючи до локального зашифрованого сховища лише сесію запитаного вебсайту. Профілі, що використовують той самий підтверджений обліковий запис на сайті, автоматично об'єднуються.

Якщо сесію заблоковано шифруванням Windows App-Bound, приватними контейнерами або неімпортованим браузером, скористайтеся **Облікові записи → Підключити обліковий запис**, щоб увійти через браузер, підключіть [супутнє розширення для браузера](../../browser-companion/guide.html) або імпортуйте файл cookie у форматі JSON/Netscape в панелі керування (ніколи не вставляйте cookie в чат зі ШІ).

<a id="local-data"></a>
## Локальні дані та ліміти запитів

Визначення вебсайтів, зашифровані облікові дані та журнал активності зберігаються в каталозі даних вашої ОС (`%LOCALAPPDATA%\hycli` у Windows, `~/Library/Application Support/hycli` у macOS, `~/.local/share/hycli` у Linux або `HYCLI_DATA_DIR`). Перевірити активний захист сховища можна будь-коли в розділі **Налаштування**.

<a id="contributing"></a>
## Розробка та перевірка

```sh
npm --prefix dashboard ci
npm --prefix dashboard run check
npm --prefix dashboard run build
cargo test --all-targets --locked
cargo build --locked --bin hycli --example dashboard_fixture
node scripts/test-e2e.mjs --full
```

Усі тести виконуються на синтетичних локальних вебсайтах і фікстурах — ніколи не тестуйте операції запису на реальних сторонніх облікових записах. Див. [джерела візуальних матеріалів](../images/README.md).

## Ліцензія та призначення

Hycli поширюється за ліцензією [Apache-2.0](../../LICENSE). Використовуйте його лише з тими вебсайтами та обліковими записами, до яких ви маєте законний доступ. Програмне забезпечення надається «як є» без жодних гарантій; автори та співавтори не несуть відповідальності за будь-які збитки, обмеження чи блокування облікових записів, що виникли внаслідок його використання.
