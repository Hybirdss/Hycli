<a id="try-it-in-30-seconds"></a>
## ลองใช้ใน 30 วินาที

```sh
# 1. ชี้ Hycli ไปยังเว็บไซต์ที่ต้องการและระบุเป้าหมาย (เตรียมทั้งการอ่านและการเขียน โดยไม่มีการแก้ไขข้อมูลจริงระหว่างเตรียม)
hycli prepare https://your-website.example --intent "ค้นหาโพสต์ บันทึกฉบับร่าง และเผยแพร่บทความ"

# 2. ดูคำสั่งอ่าน เขียน และเวิร์กโฟลว์หลายขั้นตอนทั้งหมดที่เตรียมไว้
hycli describe your-website

# 3. เรียกใช้การทำงานแบบอ่านและค้นหาได้ทันที
hycli your-website search-posts --query "บันทึกการปล่อยรุ่น"

# 4. เมื่อพร้อมจะสร้าง แก้ไข หรือลบ ให้เปิดสิทธิ์การเขียนเพียงครั้งเดียวสำหรับ CLI นี้แล้วรันได้ทันที
hycli writes your-website allow
hycli your-website create-draft --title "สวัสดีจาก Hycli" --body "สร้างอัตโนมัติจากเทอร์มินัลของฉัน"
```

หรือเชื่อมต่อ Hycli เข้ากับ **Claude Code, Cursor, Codex หรือ Windsurf** เพียงครั้งเดียวด้วย `"command": "hycli", "args": ["mcp"]` แล้วสั่งงานเอเจนต์ด้วยภาษาธรรมชาติ:
> *"ใช้ Hycli เตรียม `https://...` แสดงรายการการทำงานที่ใช้ได้ให้ดูหน่อย แล้วช่วยร่างโพสต์ใหม่ให้ด้วย"*

<a id="get-started"></a>
## เริ่มต้นใช้งาน

Hycli มาในรูปแบบไฟล์ไบนารีเนทีฟเพียงไฟล์เดียวที่รวมทั้งเอนจินสำหรับเว็บไซต์และแดชบอร์ดบนเครื่อง (`http://127.0.0.1:4318`) เข้าไว้ด้วยกัน ไม่จำเป็นต้องติดตั้ง Rust หรือ Node.js เพื่อรันแพ็กเกจที่เผยแพร่แล้ว

### ดาวน์โหลดและเรียกใช้งาน (Windows, macOS, Linux)

ดาวน์โหลดตัวติดตั้งแบบเนทีฟหรือไฟล์บีบอัดแบบพกพา (Portable) สำหรับแพลตฟอร์มของคุณได้จาก **[GitHub Releases (v0.1.0)](https://github.com/Hybirdss/Hycli/releases/tag/v0.1.0)**:

| ระบบปฏิบัติการ | สถาปัตยกรรม | ตัวติดตั้งเนทีฟ | แพ็กเกจพกพา | วิธีเริ่มต้นใช้งาน |
| --- | --- | --- | --- | --- |
| **Windows 10/11** | x64 และ ARM64 | `hycli-0.1.0-win32-*-setup.exe` | `hycli-0.1.0-win32-*.tar.gz` | รัน `*-setup.exe` (ไม่ต้องใช้สิทธิ์ผู้ดูแลระบบ เพิ่ม `hycli` ลงใน `PATH` ของผู้ใช้และเมนู Start โดยอัตโนมัติ) จากนั้นเปิด **Hycli** หรือรัน `hycli open` ใน PowerShell |
| **macOS 13+** | Apple Silicon (`arm64`) และ Intel (`x64`) | `hycli-0.1.0-darwin-*.dmg` | `hycli-0.1.0-darwin-*.tar.gz` | เปิดไฟล์ `.dmg` ลาก **Hycli.app** ไปยัง **Applications** แล้วเปิดใช้งาน (เชื่อมโยง `~/.local/bin/hycli` โดยอัตโนมัติ) |
| **Linux** | x64 และ ARM64 | `hycli-0.1.0-linux-*.deb` | `hycli-0.1.0-linux-*.tar.gz` | ติดตั้งไฟล์ `.deb` (`sudo apt install ./hycli-*.deb`) หรือแตกไฟล์ `.tar.gz` แล้วรัน `./install.sh` จากนั้นรัน `hycli open` |

### เชื่อมต่อเว็บไซต์แรกของคุณ

1. รัน `hycli open` (หรือคลิกไอคอนแอป **Hycli**) เพื่อเปิดแดชบอร์ดบนเครื่องที่ `http://127.0.0.1:4318`
2. เปิด **การเชื่อมต่อ AI** แล้วเชื่อมต่อ OpenAI, Anthropic Claude, xAI, Z.ai หรือการลงชื่อเข้าใช้ ChatGPT (Codex) บนเครื่องของคุณ
3. สำหรับเว็บไซต์ที่ต้องเข้าสู่ระบบ ให้คลิก **บัญชี → ค้นหาการเข้าสู่ระบบของฉัน** เพื่อนำเข้าเซสชันเบราว์เซอร์ของคุณเข้าสู่คลังข้อมูลเข้ารหัสบนเครื่อง
4. ป้อน URL ของเว็บไซต์และเป้าหมายเพื่อสร้างเครื่องมือ หรือคัดลอกการตั้งค่า MCP จาก **เอเจนต์เขียนโค้ด** ไปวางในผู้ช่วย AI ของคุณ

<a id="what-your-ai-can-do"></a>
## AI ของคุณทำอะไรได้บ้าง

Hycli เปลี่ยนอินเทอร์เฟซจริงของเว็บไซต์ให้เป็นคำสั่งย่อยของ CLI และเครื่องมือ MCP ที่มีคำอธิบายในตัว:

| อินเทอร์เฟซของเว็บไซต์ | ความสามารถที่เตรียมไว้ |
| --- | --- |
| REST และ OpenAPI | การทำงานแบบอ่านและเขียนที่ระบุชนิดข้อมูลตามสคีมา JSON/YAML และเอกสาร API |
| GraphQL | เอกสาร query และ mutation ที่ผ่านการแจงโครงสร้างพร้อมตัวแปร JSON ที่ระบุชนิดข้อมูล |
| หน้าเว็บ HTML และหน้าที่เรนเดอร์ด้วย JS | การดึงข้อมูลรายการ ลิงก์ การแบ่งหน้าจากตัวเลือกที่สังเกตพบ และการอ่านหน้า GET ที่เรนเดอร์ผ่านเอนจิน Chromium บนเครื่อง |
| ฟอร์มแบบ JSON และ URL-encoded | อินพุตที่มีคำอธิบาย ค่าเริ่มต้น และการส่งฟอร์มตามขอบเขตบัญชี (`POST`, `PUT`, `PATCH`, `DELETE`) |

</p>
<p align="center"><sub>เวิร์กเกอร์สามตัว กับนกน้อยหนึ่งตัวที่ยุ่งสุด ๆ</sub></p>

| ประเภทการทำงาน | พฤติกรรมการทำงาน |
| --- | --- |
| **อ่านหรือค้นหา** | ทำงานได้ทันทีเมื่อมีหลักฐานยืนยันและถูกจัดประเภทเป็นการอ่านที่ปลอดภัย |
| **สร้าง ส่ง แก้ไข หรือลบ** | ถูกค้นพบและสังเคราะห์เข้าสู่สเปกของ CLI โดยไม่ถูกเรียกใช้งานจริงเลยระหว่างการเตรียมหรือการตรวจสอบ ค่าเริ่มต้นจะถูกปิดไว้ (`writes: false`) เอเจนต์ AI จะถามคุณ **เพียงครั้งเดียวต่อหนึ่ง CLI** ว่าจะอนุญาตให้เขียนข้อมูลหรือไม่ (`hycli writes SITE allow` หรือ MCP `hycli_writes`) เมื่อเปิดแล้ว การทำงานแบบเขียนจะรันได้โดยตรงเมื่อคุณสั่ง |
| **ผลกระทบไม่ชัดเจน** | ถูกพักไว้เพื่อรอการตรวจสอบก่อนส่งคำขอ |
| **ด่านตรวจสอบสิทธิ์หรือการจำกัดอัตรา (Rate limit)** | สลับกลยุทธ์การส่งข้อมูลทันที (HTTP → `window.fetch` ในหน้าเว็บ → Chromium แบบพรางตัว) หรือหยุดพักอย่างปลอดภัย |

ดูรูปแบบคำขอและกฎการดึงข้อมูลที่รองรับได้ที่[ข้อมูลอ้างอิงการทำงาน](../SITESPEC.md)

<a id="common-concerns"></a>
## ข้อกังวลที่พบบ่อยและวิธีที่ Hycli แก้ไข

การเชื่อมต่อเอเจนต์ AI เข้ากับเว็บไซต์จริงและบัญชีที่ลงชื่อเข้าใช้ไว้มักทำให้เกิดคำถามสำคัญ นี่คือวิธีที่ Hycli จัดการแต่ละประเด็นตั้งแต่ระดับโครงสร้าง:

### 1. "AI จะเผลอโพสต์ แก้ไข หรือลบข้อมูลในบัญชีของฉันโดยไม่ตั้งใจไหม?"
- **ไม่มีการแก้ไขข้อมูลจริงเป็นอันขาดระหว่างการสร้างและตรวจสอบ CLI:** ขณะเตรียมหรือตรวจสอบเว็บไซต์ (`hycli prepare`, `hycli request`, `hycli recon`, `hycli check`) Hycli จะค้นหาและคอมไพล์ทั้งการทำงานแบบอ่านและเขียนเข้าสู่สเปกของ CLI แต่ **จะไม่ส่งคำขอเขียนข้อมูลไปยังเซิร์ฟเวอร์จริงเด็ดขาด** แม้แต่การแก้ไขที่แฝงมากับการอ่าน (เช่น เส้นทาง `GET` ที่มีคำว่า `/delete`, คำสั่ง GraphQL `mutation` หรือฟอร์ม HTML `<form method="post">`) ก็จะถูกบล็อกไม่ให้ทำงานระหว่างการตรวจสอบ
- **ยืนยันการเปิดสิทธิ์เขียนเพียงครั้งเดียวต่อหนึ่ง CLI:** CLI ของเว็บไซต์ที่สร้างใหม่ทุกตัวจะเริ่มต้นด้วย `writes: false` เมื่อเอเจนต์ AI จำเป็นต้องรันการทำงานแบบเขียนบน CLI นั้นเป็นครั้งแรก ระบบจะถามคุณ **เพียงครั้งเดียวสำหรับ CLI นั้น**: *"อนุญาตการทำงานแบบเขียนสำหรับ `<site>` หรือไม่?"* ต่อเมื่อคุณยืนยันแล้วเท่านั้น ระบบจึงจะเปิด `hycli writes <site> allow` (หรือ MCP `hycli_writes`) เพื่อให้รันการเขียนได้โดยตรง คุณสามารถเพิกถอนสิทธิ์การเขียนได้ทุกเมื่อด้วย `hycli writes <site> deny` หรือสวิตช์ **อนุญาตให้เปลี่ยนแปลง** ในแดชบอร์ด
- **ไม่ลองส่งคำขอเขียนซ้ำโดยอัตโนมัติ:** คำขอเขียนที่ล้มเหลวหรือถูกขัดจังหวะจะไม่ถูกลองใหม่โดยอัตโนมัติเด็ดขาด หากการเชื่อมต่อหลุดหลังจากส่งคำขอเปลี่ยนแปลงไปแล้ว Hycli จะรายงาน `action_outcome_unknown` เพื่อให้คุณตรวจสอบบนเว็บไซต์ก่อน แทนที่จะสร้างคำสั่งซื้อหรือโพสต์ซ้ำ

### 2. "Hycli จะส่งคุกกี้ โทเค็นการเข้าสู่ระบบ หรือคีย์ API ของฉันไปยังโมเดล AI (LLM) ไหม?"
- **ข้อมูลลับไม่เคยถูกส่งเข้าสู่พรอมต์ของ LLM:** คุกกี้ของเบราว์เซอร์, โทเค็นใน `localStorage` / `sessionStorage` และคีย์ API จะถูกเก็บไว้เฉพาะในคลังข้อมูลเข้ารหัสบนเครื่องของคุณเท่านั้น (เข้ารหัสผ่านระบบจัดการคีย์ของ OS เช่น Windows Credential Manager, macOS Keychain, Linux Secret Service หรือจำกัดสิทธิ์ไฟล์ไว้ที่ `0600` เฉพาะผู้ใช้ปัจจุบันเท่านั้น)
- **สูตรการเชื่อมต่อแบบสัญลักษณ์ (`ConnectionRecipe`):** โมเดล AI จะเห็นเฉพาะป้ายกำกับบัญชี ชื่อคีย์ในที่เก็บข้อมูล และโครงสร้างคำตอบที่ถูกปิดบังข้อมูลสำคัญแล้วเท่านั้น โมเดลจะสร้าง `ConnectionRecipe` แบบสัญลักษณ์ (ที่อ้างอิงเฉพาะชื่อคุกกี้หรือชื่อโทเค็น) แล้ว Hycli จึงจะฉีดค่าข้อมูลลับจริงภายในเครื่องตอนสั่งรัน พร้อมทั้งลบข้อมูลลับออกจากผลลัพธ์และบันทึก (Log) ทั้งหมดโดยอัตโนมัติ
- **การนำเข้าเซสชันแบบอ่านอย่างเดียวตามขอบเขตเว็บไซต์:** การนำเข้าเซสชันเบราว์เซอร์จะอ่านเฉพาะคุกกี้และที่เก็บข้อมูลของโดเมนเป้าหมายจากสแนปช็อตแบบอ่านอย่างเดียวชั่วคราว โดยไม่ลดทอนความปลอดภัยของเบราว์เซอร์หรือส่งออกข้อมูลของเว็บไซต์อื่น

### 3. "การดึงข้อมูลจะทำให้ติด CAPTCHA หรือทำให้บัญชีของฉันถูกแบนไหม?"
- **ไม่มีการทำ Fuzzing หรือสุ่มเดาเส้นทางแบบ Brute-force:** Hycli ไม่เคยเดารายชื่อเอนด์พอยต์หรือยิงทดสอบเซิร์ฟเวอร์จริงแบบสุ่ม แต่จะเรียนรู้จากเอกสารที่เชื่อมโยงไว้ สคีมา OpenAPI/GraphQL ชุดไฟล์ JS แบบสแตติก และรูปแบบเครือข่ายของเบราว์เซอร์ที่สังเกตเห็นเท่านั้น
- **ส่งคำขอตามลำดับและจำกัดความเร็ว:** คำขอจะถูกจัดคิวตามลำดับและจำกัดอัตราต่อเว็บไซต์และต่อบัญชี โดยเคารพเฮดเดอร์ `Retry-After` และจำกัดจำนวนครั้งการลองอ่านซ้ำรวมถึงขนาดของคำตอบอย่างเข้มงวด
- **ระบบตัดวงจรกลยุทธ์และการรันผ่านบริบทเบราว์เซอร์จริง:** เมื่อการส่งคำขอ HTTP ปกติพบกับรหัส 403/429 หรือด่านตรวจจับบอท (เช่น Cloudflare, Akamai Bot Manager) Hycli จะไม่วนซ้ำคำขอที่ถูกบล็อกเดิม ระบบตัดวงจรจะสลับช่องทางการส่งข้อมูลทันที—โดยรัน `window.fetch(..., { credentials: 'include' })` ภายในบริบทเบราว์เซอร์ที่ยืนยันตัวตนแล้วของคุณ หรือใช้เอนจิน Chromium แบบพรางตัวบนเครื่อง—หรือหยุดพักอย่างปลอดภัยเพื่อปกป้องบัญชีของคุณ

### 4. "การเปลี่ยนเส้นทาง (Redirect) จะทำให้เซสชันรั่วไหล หรือการแชร์ไฟล์สเปกจะเปิดเผยพาธในคอมพิวเตอร์ของฉันไหม?"
- **การผูกติดกับต้นทาง (Origin) อย่างเข้มงวด:** เฮดเดอร์ยืนยันตัวตนและคุกกี้จะถูกล็อกไว้กับต้นทางเป้าหมายเท่านั้น และจะถูกลบออกทันทีเมื่อมีการเปลี่ยนเส้นทางข้ามต้นทาง (Cross-origin redirect) ช่วง IP เครือข่ายส่วนตัวและภายในเครื่องจะถูกบล็อกโดยค่าเริ่มต้น เว้นแต่จะระบุ `--allow-local` อย่างชัดเจน
- **ไฟล์สเปกที่พกพาได้อย่างปลอดภัย:** พาธของไฟล์โปรแกรมเบราว์เซอร์และโปรไฟล์บนเครื่องจะถูกเก็บไว้ในสถานะเฉพาะเครื่องเท่านั้น และไม่เคยถูกเขียนลงในไฟล์ `SiteSpec` สำหรับแชร์ต่อ

### 5. "เมื่อเซสชันการเข้าสู่ระบบหมดอายุ AI จะสิ้นเปลืองโทเค็นเพื่อลองใหม่ซ้ำ ๆ ไหม?"
- **การตรวจสอบสถานะแบบกำหนดผลได้โดยไม่ใช้ AI (`hycli check`):** `hycli check` (และ MCP `hycli_check`) จะเล่นซ้ำลำดับการอ่านที่ยืนยันแล้วโดยไม่ต้องเรียกใช้ LLM และแยกแยะอย่างชัดเจนระหว่าง `signed_out` (เซสชันหมดอายุ ต้องเชื่อมต่อบัญชีใหม่) กับ `site_changed` (โครงสร้างเว็บไซต์เปลี่ยน ต้องซ่อมแซมสเปก), `blocked` และ `unreachable`

<a id="use-hycli-with-your-ai"></a>
## ใช้ Hycli กับ AI ของคุณ

เพิ่ม Hycli ลงในไคลเอนต์ MCP ของคุณ (**เอเจนต์เขียนโค้ด → ดูการตั้งค่าการเชื่อมต่อ** จะแสดงพาธที่ถูกต้องสำหรับระบบปฏิบัติการของคุณ):

```json
{
  "mcpServers": {
    "hycli": {
      "command": "hycli",
      "args": ["mcp"]
    }
  }
}
```

ใช้ `hycli mcp --sites-only` เพื่อเปิดเผยเฉพาะเครื่องมือเว็บไซต์ที่ติดตั้งไว้แล้ว หรือเพิ่ม `--only-site SITE` เพื่อจำกัดไว้เฉพาะเว็บไซต์เดียว เซิร์ฟเวอร์ MCP มีเครื่องมือ `hycli_prepare`, `hycli_writes` (เปิดสิทธิ์การเขียนครั้งเดียวต่อ CLI หลังจากถามคุณแล้ว), `hycli_run`, `hycli_check`, `hycli_result` และ `hycli_activity`—และไม่เคยเปิดเผยเครื่องมือสำหรับอ่านข้อมูลรับรองใด ๆ

จากเทอร์มินัล ทุกเวิร์กโฟลว์ทำงานในรูปแบบเดียวกัน:

```sh
hycli prepare https://your-website.example --intent "ค้นหาเอกสารอ้างอิงที่บันทึกไว้"
hycli request SITE "เพิ่มฟีเจอร์แก้ไขเนื้อหาโพสต์ บันทึกฉบับร่าง และเผยแพร่บทความ"
hycli describe SITE
hycli SITE ACTION --help
hycli writes SITE allow
hycli SITE ACTION --query "design systems"
hycli check SITE
```

<a id="browser-sign-in"></a>
## ลงชื่อเข้าใช้ผ่านเบราว์เซอร์

Hycli จะค้นหาโปรไฟล์ของ Chrome, Chromium, Edge, Brave, Vivaldi, Arc, Whale และ Firefox บนเครื่อง (รวมถึงไบนารี Chromium แบบพรางตัวบนเครื่องเมื่อติดตั้งไว้) ทั้งบน Windows, macOS และ Linux โดยนำเข้าเฉพาะเซสชันของเว็บไซต์ที่ร้องขอเข้าสู่คลังข้อมูลเข้ารหัสบนเครื่องเท่านั้น โปรไฟล์ที่ใช้บัญชีเว็บไซต์เดียวกันซึ่งผ่านการยืนยันแล้วจะถูกรวมให้เหลือรายการเดียวโดยอัตโนมัติ

หากเซสชันถูกล็อกด้วยการเข้ารหัส Windows App-Bound คอนเทนเนอร์ส่วนตัว หรือเบราว์เซอร์ที่ยังไม่รองรับการนำเข้าโดยตรง ให้ไปที่ **บัญชี → เชื่อมต่อบัญชี** เพื่อลงชื่อเข้าใช้ผ่านเบราว์เซอร์ เชื่อมต่อ[ส่วนขยายเบราว์เซอร์คู่หู](../../browser-companion/guide.html) หรือนำเข้าไฟล์คุกกี้รูปแบบ JSON/Netscape ในแดชบอร์ด (อย่าวางเนื้อหาคุกกี้ลงในช่องแชท AI โดยตรงเด็ดขาด)

<a id="local-data"></a>
## ข้อมูลบนเครื่องและข้อจำกัดคำขอ

นิยามเว็บไซต์ ข้อมูลรับรองที่เข้ารหัสแล้ว และบันทึกกิจกรรมจะถูกเก็บไว้ในไดเรกทอรีข้อมูลของระบบปฏิบัติการ (`%LOCALAPPDATA%\hycli` บน Windows, `~/Library/Application Support/hycli` บน macOS, `~/.local/share/hycli` บน Linux หรือ `HYCLI_DATA_DIR`) คุณสามารถตรวจสอบพาธปัจจุบันและสถานะการปกป้องคลังข้อมูลได้ทุกเมื่อในเมนู **การตั้งค่า**
