<a id="get-started"></a>
## เริ่มต้นใช้งาน

**[ดาวน์โหลด v0.1.0 · Linux x64](https://github.com/Hybirdss/Hycli/releases/tag/v0.1.0)** · glibc ≥ 2.39 · [SHA-256](https://github.com/Hybirdss/Hycli/releases/download/v0.1.0/hycli-0.1.0-linux-x64.tar.gz.sha256)

Hycli เป็นแอปพลิเคชัน Rust ที่มีเว็บแดชบอร์ดทำงานบนเครื่อง สร้างแดชบอร์ดและไฟล์ปฏิบัติการจากซอร์สโค้ดที่เช็กเอาต์ไว้นี้:

```sh
node scripts/build.mjs
./dist/hycli dashboard
```

แดชบอร์ดจะเปิดที่ `http://127.0.0.1:4318` ใช้ `hycli dashboard --no-open` เพื่อแสดงที่อยู่โดยไม่เปิดเบราว์เซอร์ หรือใช้ `--port 4320` เพื่อเลือกพอร์ตอื่น กลไกสำหรับเว็บไซต์และแดชบอร์ดรวมอยู่ในไฟล์ปฏิบัติการเดียวกัน

1. เปิด **การเชื่อมต่อ AI** แล้วเชื่อมต่อผู้ให้บริการ
2. เพิ่มที่อยู่เว็บไซต์ แล้วเลือก AI ที่จะเตรียมเว็บไซต์นั้น
3. ตรวจสอบการทำงานที่ใช้ได้ เรียกใช้ในแดชบอร์ด หรือเปิด **เอเจนต์เขียนโค้ด** เพื่อคัดลอกการตั้งค่า MCP เพียงครั้งเดียว

สำหรับเว็บไซต์ที่ต้องลงชื่อเข้าใช้ ให้เชื่อมต่อบัญชีจาก **บัญชี** เว็บไซต์หนึ่งแห่งสามารถบันทึกหลายบัญชีได้ และคุณเลือกได้ว่าจะให้เครื่องมือใช้บัญชีใด

<a id="what-your-ai-can-do"></a>
## AI ของคุณทำอะไรได้บ้าง

Hycli เปลี่ยนการทำงานของเว็บไซต์ที่รองรับให้เป็นเครื่องมือที่มีชื่อและชนิดข้อมูล คำอธิบายที่ AI เขียนจะบอกว่าแต่ละการทำงานทำอะไร ต้องใช้ข้อมูลใด และส่งคืนผลลัพธ์อะไร

ตัวทำงาน AI อิสระสามตัวรับผิดชอบการอ่านและค้นหา ขั้นตอนการทำงานที่มีประโยชน์ และหลักฐานยืนยันบัญชีตามลำดับ แดชบอร์ดแสดงขั้นตอนที่เสร็จแล้ว สถานะของตัวทำงานแต่ละตัว เวลาที่ผ่านไป และบันทึกการทำงานที่เข้าใจง่าย งานผ่าน CLI และ MCP ปรากฏในประวัติกิจกรรมเดียวกัน

<p align="center">
  <img src="../../docs/images/preparation.gif" alt="เวิร์กเกอร์สามตัว กับนกน้อยหนึ่งตัวที่ยุ่งสุด ๆ" width="100%" />
</p>
<p align="center"><sub>เวิร์กเกอร์สามตัว กับนกน้อยหนึ่งตัวที่ยุ่งสุด ๆ</sub></p>

การเตรียมอ้างอิงข้อมูลที่มีอยู่จริงจากเว็บไซต์ ได้แก่ เอกสารที่เชื่อมโยงไว้ สคีมา API, JavaScript ที่เผยแพร่ และโครงสร้างคำขอที่ส่วนขยายเบราว์เซอร์สังเกตได้ ระบบอาจอ่านข้อมูลในขอบเขตจำกัดเพื่อตรวจสอบการทำงาน แต่จะไม่สร้างระเบียนทดสอบ แก้ไขเนื้อหา ลบวัตถุ เดารายการเอนด์พอยต์จำนวนมาก หรือทำ fuzz testing กับเซิร์ฟเวอร์ที่ใช้งานจริง

| การทำงาน | พฤติกรรม |
| --- | --- |
| อ่านหรือค้นหา | ทำงานโดยอัตโนมัติเมื่อมีหลักฐานรองรับและจัดประเภทเป็นการอ่าน |
| สร้าง ส่ง แก้ไข หรือลบ | แสดงเว็บไซต์ บัญชี การทำงาน และค่าอินพุตที่กำหนดแล้วให้ผู้ใช้อนุมัติ |
| ผลกระทบไม่ชัดเจน | ต้องตรวจสอบก่อนส่งคำขอ |
| การยืนยันตัวตน ด่านตรวจสอบ หรือการจำกัดคำขอ | หยุดคำขอที่ได้รับผลกระทบชั่วคราว เพื่อให้คุณเชื่อมต่อใหม่หรือรอ |

การอนุมัติใช้ได้กับคำขอที่ตรงกันเพียงหนึ่งรายการ หมดอายุหลังห้านาที และใช้ได้ครั้งเดียว การเปลี่ยนอินพุต บัญชี ข้อมูลการลงชื่อเข้าใช้ที่บันทึกไว้ หรือนิยามเครื่องมือที่ติดตั้งจะทำให้การอนุมัติใช้ไม่ได้ การเรียกใช้ผ่าน CLI, MCP และแดชบอร์ดใช้ขอบเขตเดียวกัน การเขียนข้อมูลจะไม่มีการลองใหม่โดยอัตโนมัติ

การรองรับขึ้นอยู่กับเว็บไซต์ หน้าที่ไม่มีเอกสารที่ใช้ได้หรือการทำงานที่สังเกตพบ อาจต้องใช้เบราว์เซอร์ที่ลงชื่อเข้าใช้แล้ว SiteSpec ที่จัดเตรียมให้ หรือการเตรียมเพิ่มเติม Hycli จะแจ้งสิ่งที่รองรับได้ แทนการอ้างว่าทุกเว็บไซต์มี API พร้อมใช้

### ขอบเขตที่รองรับ

รองรับ OpenAPI แบบ JSON หรือ YAML, REST, GraphQL และคำขอ JSON หรือฟอร์มที่เข้ารหัส URL ดึงรายการ ลิงก์ และหน้าถัดไปจาก HTML ด้วยตัวเลือกที่สังเกตได้ และอ่านหน้า GET ที่เรนเดอร์ด้วย Chromium ในเครื่องได้ หากการอ่านระหว่างเตรียมล้มเหลว AI จะตรวจหลักฐาน แก้คำจำกัดความ และตรวจสอบอีกครั้ง

ยังไม่รองรับลำดับการคลิกเบราว์เซอร์แบบอิสระ การอัปโหลด multipart หรือการดาวน์โหลดไบนารี แพ็กเกจไม่รวมบัญชีหรือ CLI ที่สร้างไว้ก่อนแล้ว

| การเชื่อมต่อ | การลงชื่อเข้าใช้ |
| --- | --- |
| ChatGPT · คีย์ API | คีย์ API ของ OpenAI ของคุณ |
| Claude | คีย์ API ของ Anthropic ของคุณ |
| xAI | คีย์ API ของ xAI ของคุณ |
| Z.ai | คีย์ API ของ Z.ai ของคุณ |
| Z.ai Coding Plan | คีย์ API ของ Z.ai Coding Plan ของคุณ |
| ChatGPT · เข้าสู่ระบบ | การลงชื่อเข้าใช้ ChatGPT ที่จัดการโดย Codex app-server ที่ติดตั้งไว้ |

เลือกโมเดลในแดชบอร์ด รวมถึงโมเดลที่เปิดให้บัญชีของคุณโดยเฉพาะ การตรวจสอบการเชื่อมต่อจะยืนยันผู้ให้บริการและโมเดลที่เลือก ผู้ให้บริการ API จะคิดค่าบริการตามการใช้งานกับบัญชีของคุณที่ผู้ให้บริการนั้น

การเชื่อมต่อ Codex ใช้โปรโตคอล app-server อย่างเป็นทางการ Hycli ไม่อ่านหรือคัดลอกโทเค็น OAuth ของ Codex การอนุมานทำงานในเธรดชั่วคราวที่ปิดการเรียกใช้ไฟล์ เชลล์ เบราว์เซอร์ แอปพลิเคชัน และ MCP การเตรียมเว็บไซต์ดำเนินการด้วยเครื่องมืออ่านที่ Hycli ควบคุม

## ใช้ Hycli กับ AI ของคุณ

**เอเจนต์เขียนโค้ด → ดูการตั้งค่าการเชื่อมต่อ**

การเชื่อมต่อ MCP แบบทั่วไปใช้ได้ทั้งการเตรียมเว็บไซต์และเรียกใช้การทำงาน เชื่อมต่อเอเจนต์ครั้งเดียวเพื่อให้เอเจนต์เตรียมเครื่องมือที่ขาด ติดตามความคืบหน้า และใช้การทำงานใหม่ได้

```sh
hycli mcp
```

ใช้ `--sites-only` เพื่อเปิดให้ใช้เฉพาะการทำงานที่ติดตั้งแล้ว การเชื่อมต่อด้านล่างจำกัดไว้ที่เว็บไซต์เดียว

```sh
hycli mcp --sites-only --only-site SITE
```

```json
{
  "mcpServers": {
    "hycli": {
      "command": "hycli",
      "args": [
        "mcp"
      ]
    }
  }
}
```

หากไม่มี `hycli` ใน PATH ของเอเจนต์ ให้ใช้พาธไฟล์โปรแกรมที่แสดงในแดชบอร์ด

ใช้ขั้นตอนเดียวกันผ่าน CLI ได้ โดยแทน URL ตัวอย่าง, `SITE` และ `ACTION` ด้วยเว็บไซต์ของคุณและชื่อที่ได้จาก `describe`

```sh
hycli prepare https://your-website.example --intent "ค้นหาเอกสารอ้างอิงที่บันทึกไว้"
hycli request SITE "Add draft editing and publishing with full post content"
hycli describe
hycli describe SITE ACTION
hycli SITE ACTION --help
hycli run SITE ACTION --arg query="design systems"
hycli jobs show JOB_ID --watch
```

ใน MCP ให้ส่ง URL และ `intent` ไปยัง `hycli_prepare` แล้วติดตามด้วย `hycli_job` หรือ `hycli_result` ส่วน `hycli_run` เรียกใช้การทำงานใหม่ได้ก่อนที่ไคลเอนต์จะรีเฟรชรายการเครื่องมือ หากต้องใช้ ID ภายใน ให้ค้นหาผ่านการแสดงรายการหรือการค้นหาที่เกี่ยวข้องก่อน

การทำงานที่เปลี่ยนข้อมูลจะคืนใบคำขอให้ตรวจสอบในแดชบอร์ด ติดตามผลจากใบคำขอเดิมโดยไม่ส่งซ้ำ การอ่านที่ล้มเหลวหรือคำตอบที่ไม่ตรงตามคาดจะทำให้ CLI รายงานความล้มเหลวเช่นกัน

## ลงชื่อเข้าใช้ผ่านเบราว์เซอร์

การเตรียมเว็บไซต์เริ่มจากตรวจสอบระบบปฏิบัติการปัจจุบัน เบราว์เซอร์ที่กำลังทำงานหรือได้ลงทะเบียนไว้ และโปรไฟล์ที่ใช้งานได้ AI เลือกใช้ความสามารถเหล่านี้เพื่ออ่านเอกสาร แสดงหน้าเว็บ นำเข้าเซสชันของเว็บไซต์ และตรวจสอบการเชื่อมต่อ พาธของเบราว์เซอร์และโปรไฟล์ยังคงอยู่บนเครื่อง การกำหนดค่าเว็บไซต์ที่สร้างขึ้นไม่ขึ้นกับพาธการติดตั้งของผู้พัฒนา

สามารถนำเข้าคุกกี้และข้อมูลจัดเก็บตามต้นทางจาก Chrome, Chromium, Edge, Brave และ Firefox เมื่อเข้าถึงได้ เฉพาะเซสชันของเว็บไซต์ที่ร้องขอเท่านั้นที่เข้าสู่คลังข้อมูลในเครื่องของ Hycli Hycli เลือกตัวตนที่ยืนยันแล้วเพียงหนึ่งรายการโดยอัตโนมัติ และนับโปรไฟล์ของตัวตนเดียวกันเป็นตัวเลือกบัญชีเดียว ระบบคงการเลือกบัญชีเดิมไว้ แต่หากมีตัวตนที่ยืนยันแล้วต่างกันจะต้องเลือกบัญชี

ใน **บัญชี → เชื่อมต่อบัญชี** เลือก **ค้นหาการเข้าสู่ระบบของฉัน** เพื่อค้นหาอีกครั้ง หากไม่พบเซสชันที่ใช้ได้ ให้เลือก **เปิดหน้าเข้าสู่ระบบของเว็บไซต์** เพื่อเปิดเว็บไซต์ในเบราว์เซอร์เริ่มต้น Hycli จะตรวจสอบซ้ำขณะที่กล่องโต้ตอบเปิดอยู่ และเตรียมเว็บไซต์ต่อเมื่อบัญชีที่เลือกได้รับการยืนยันแล้วเท่านั้น การเปิดแท็บอย่างเดียวไม่ถือว่าเข้าสู่ระบบสำเร็จ

เซสชันที่ได้รับการป้องกันโดยระบบปฏิบัติการ ผูกกับเบราว์เซอร์ เป็นเซสชันส่วนตัว หรืออยู่ในคอนเทนเนอร์ อาจต้องใช้ส่วนขยายเบราว์เซอร์ เลือกแท็บส่วนขยายแล้วสร้างรหัสเชื่อมต่อ จากนั้นเปิดส่วนขยายในโปรไฟล์ที่ลงชื่อเข้าใช้แล้ว กรอกรหัส และอนุญาตให้เข้าถึงเว็บไซต์นั้น การนำเข้าโดยตรงจะไม่ข้ามการป้องกัน Windows App-Bound หรือลดความปลอดภัยของโปรไฟล์เบราว์เซอร์

- **Chrome และ Edge:** แตกไฟล์แพ็กเกจ แล้วใช้ **โหลดส่วนขยายที่แตกไฟล์แล้ว** บนหน้าส่วนขยายของเบราว์เซอร์
- **Firefox:** ใช้แพ็กเกจ Firefox แล้วเลือก **โหลดส่วนเสริมชั่วคราว** ใน `about:debugging` ส่วนขยายชั่วคราวจะถูกลบเมื่อเริ่ม Firefox ใหม่ รุ่นนี้ยังไม่มีการแจกจ่ายผ่านร้านค้าที่ลงลายมือชื่อแล้ว
- **ไฟล์คุกกี้:** นำเข้าไฟล์คุกกี้รูปแบบ JSON และ Netscape เป็นทางเลือกสำรองได้ นำเข้าไฟล์โดยตรงในแดชบอร์ด อย่าวางเนื้อหาลงในการสนทนากับ AI

เบราว์เซอร์ส่งข้อมูลเซสชันตรงไปยังคลังข้อมูลรับรองบนเครื่อง โมเดลได้รับป้ายกำกับบัญชี ชื่อและโครงสร้างของคีย์ในเครื่อง และผลลัพธ์เครื่องมือที่ลบค่าข้อมูลรับรองแล้ว โมเดลสร้างขั้นตอนการเชื่อมต่อที่อ้างถึงค่าในเครื่องเหล่านั้นได้โดยไม่ต้องรับค่า ระบบปฏิบัติตามขอบเขต พาธ วันหมดอายุ และข้อมูลพาร์ทิชันของคุกกี้ที่รองรับ ส่วนเฮดเดอร์ยืนยันตัวตนจะถูกจำกัดไว้ที่ต้นทางเดิม

ตัวตนของบัญชีอ้างอิงจากคำตอบเกี่ยวกับบัญชีปัจจุบันที่ได้รับจริงจากเว็บไซต์ ชื่อโปรไฟล์เบราว์เซอร์ไม่ถือเป็นตัวตนบนเว็บไซต์ที่ยืนยันแล้ว หากยังระบุบัญชีไม่ได้ Hycli จะแจ้งให้ทราบ หลังเชื่อมต่อ การท่องเว็บตามปกติสามารถให้คำตอบเกี่ยวกับบัญชีและโครงสร้างคำขอที่ใช้ได้ โดยไม่เปิดเผยค่าในคำขอ เฮดเดอร์ หรือเนื้อหาคำตอบแก่โมเดลที่ใช้เตรียมเว็บไซต์

เว็บไซต์อาจต้องใช้ข้อมูลรับรอง API แยกต่างหากตามเอกสาร หรือความสามารถของเบราว์เซอร์ที่ไม่มีในเครื่อง การเตรียมจะบันทึกผลการเชื่อมต่อและการอ่านจริง การดึงหน้าแรกได้หรือการที่ API ส่งหน้าลงชื่อเข้าใช้กลับมาไม่ได้หมายความว่าการผสานรวมพร้อมใช้งาน [คู่มือการตั้งค่าเบราว์เซอร์](../../browser-companion/guide.html) อธิบายขั้นตอนของส่วนขยายและข้อจำกัด

## ภาษา

แดชบอร์ดรองรับ 20 ภาษาที่เชื่อมโยงไว้ด้านบน รวมถึงภาษาอาหรับที่เขียนจากขวาไปซ้าย ภาษาเริ่มต้นคือภาษาอังกฤษ การเลือกของคุณบันทึกไว้บนอุปกรณ์นี้ และเตรียมคำอธิบาย AI ในภาษาที่เลือกได้

<a id="local-data"></a>
## ข้อมูลบนเครื่องและข้อจำกัดคำขอ

นิยามเว็บไซต์ เมทาดาทาบัญชี และกิจกรรมเก็บอยู่ในไดเรกทอรีข้อมูลบนเครื่อง ตั้งค่า `HYCLI_DATA_DIR` เพื่อเลือกตำแหน่งอื่น ใช้ **การตั้งค่า** เพื่อดูตำแหน่งปัจจุบันและการป้องกันข้อมูลรับรอง

เมื่อใช้ได้ คลังข้อมูลรับรองจะใช้คีย์เข้ารหัสที่มีพวงกุญแจของระบบปฏิบัติการรองรับ หากใช้พวงกุญแจไม่ได้ ระบบจะแจ้งชัดเจนว่าที่เก็บได้รับการป้องกันด้วยสิทธิ์ไฟล์เท่านั้น ไดเรกทอรีส่วนตัวและไฟล์ข้อมูลรับรองจะจำกัดให้เฉพาะผู้ใช้ระบบปฏิบัติการปัจจุบันเข้าถึงได้ คลังที่เข้ารหัสอยู่แล้วจะไม่ถูกแทนที่อย่างเงียบ ๆ เมื่อปลดล็อกไม่ได้

คำขอจะดำเนินการตามลำดับและควบคุมจังหวะต่อเว็บไซต์และบัญชี พร้อมโควตาเพิ่มเติมสำหรับทั้งเว็บไซต์ Hycli ปฏิบัติตาม `Retry-After` จำกัดขนาดคำตอบและจำนวนครั้งที่ลองอ่านใหม่ และหยุดชั่วคราวเมื่อยืนยันตัวตนไม่สำเร็จหรือพบด่านตรวจสอบของเว็บไซต์ การเตรียมเว็บไซต์จะไม่สลับบัญชี ปลอมลายนิ้วมือ หรือข้ามด่านตรวจสอบเพื่อหลบข้อจำกัด มาตรการเหล่านี้ลดภาระที่หลีกเลี่ยงได้ แต่ไม่อาจรับประกันว่าเว็บไซต์จะไม่จำกัดบัญชีเลย

ที่อยู่เว็บไซต์ในเครือข่ายส่วนตัวและบนเครื่องถูกปิดใช้งานโดยค่าเริ่มต้น สำหรับเว็บไซต์ที่โฮสต์เองและเชื่อถือได้ ให้ระบุ `--allow-local` อย่างชัดเจนเมื่อเปิดแดชบอร์ดหรือเซิร์ฟเวอร์ MCP

## การพัฒนาและการตรวจสอบ

```sh
npm --prefix dashboard ci
npm --prefix dashboard run check
npm --prefix dashboard run build
cargo test --all-targets --locked
cargo build --locked --bin hycli --example dashboard_fixture
node scripts/test-e2e.mjs --full
```

การทดสอบใช้เว็บไซต์บนเครื่องและคำตอบผู้ให้บริการที่สร้างขึ้นเพื่อทดสอบ ครอบคลุมการผูกการอนุมัติและป้องกันการใช้ซ้ำ การลบข้อมูลลับ การเปลี่ยนเส้นทาง การจำกัดอัตรา การไม่ลองเขียนใหม่ การป้องกันเซสชันเบราว์เซอร์ และสัญญารูปแบบคำตอบของผู้ให้บริการ อย่าใช้บัญชีจริงสร้าง แก้ไข หรือลบเนื้อหาเพียงเพื่อทดสอบ Hycli

## สัญญาอนุญาตและวัตถุประสงค์การใช้งาน

Hycli เผยแพร่ภายใต้สัญญาอนุญาต [Apache-2.0](../../LICENSE)

Hycli มีไว้เพื่อสร้างและใช้เครื่องมือบรรทัดคำสั่งที่ทำให้เว็บไซต์ใช้งานง่ายขึ้น ใช้กับเว็บไซต์และบัญชีที่คุณได้รับอนุญาตให้เข้าถึง

ซอฟต์แวร์นี้ให้บริการตามสภาพโดยไม่มีการรับประกัน ภายในขอบเขตที่กฎหมายอนุญาต ผู้เขียนและผู้ร่วมพัฒนาไม่ต้องรับผิดต่อความสูญเสียหรือปัญหาอื่นที่เกิดจากการใช้งาน คุณเป็นผู้รับผิดชอบต่อวิธีใช้ซอฟต์แวร์นี้

เท่าที่กฎหมายอนุญาต ผู้เขียนและผู้มีส่วนร่วมไม่รับผิดชอบต่อการแบน ระงับ หรือจำกัดบัญชีที่เกิดจากการใช้ Hycli อย่าใช้ Hycli เพื่อแฮ็ก เข้าถึงโดยไม่ได้รับอนุญาต หรือโจมตี
