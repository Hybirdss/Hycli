ウェブサイトを追加すると、HycliがAIで使える操作を用意し、それぞれの役割を説明します。ウェブサイト、ログイン、実行結果をローカルのダッシュボードでまとめて管理できます。

| 接続 | 準備 | 利用 |

<a id="get-started"></a>
## はじめに

**[ダウンロード v0.1.0 · Linux x64](https://github.com/Hybirdss/Hycli/releases/tag/v0.1.0)** · glibc ≥ 2.39 · [SHA-256](https://github.com/Hybirdss/Hycli/releases/download/v0.1.0/hycli-0.1.0-linux-x64.tar.gz.sha256)

Hycliはローカルのウェブダッシュボードを備えたRustアプリケーションです。チェックアウトしたこのソースから、ダッシュボードと実行ファイルをビルドします。

```sh
node scripts/build.mjs
./dist/hycli dashboard
```

ダッシュボードは `http://127.0.0.1:4318` で開きます。ブラウザーを開かずにアドレスだけを表示するには `hycli dashboard --no-open`、別のポートを使うには `--port 4320` を指定してください。ウェブサイトエンジンとダッシュボードは同じ実行ファイルに含まれます。

1. **AI接続**を開き、プロバイダーを接続します。
2. ウェブサイトのアドレスを追加し、準備を担当するAIを選びます。
3. 利用可能な操作を確認します。ダッシュボードで実行するか、**コーディングエージェント**を開いてMCP設定を一度コピーします。

ログインが必要なウェブサイトでは、**アカウント**からアカウントを接続してください。1つのウェブサイトに複数のアカウントを保存でき、ツールで使うアカウントを選べます。

<a id="what-your-ai-can-do"></a>
## AIでできること

Hycliは、対応するウェブサイトの操作を、名前と型を持つツールに変換します。AIが作成する説明には、各操作の目的、必要な情報、返される結果が記載されます。

3つの独立したAIワーカーが、読み取りと検索、有用なワークフロー、アカウントの確認資料をそれぞれ担当します。ダッシュボードには完了した段階、各ワーカーの状態、経過時間、わかりやすい作業メモが表示されます。CLIとMCPからの作業も同じアクティビティ履歴に表示されます。

準備では、リンク先のドキュメント、APIスキーマ、公開されたJavaScript、ブラウザー連携ツールが観測したリクエストの構造など、ウェブサイトから実際に得られる情報を使います。操作の確認のため、範囲を限定した読み取りを行うことがあります。テスト用レコードの作成、コンテンツの編集、オブジェクトの削除、大量のエンドポイントの推測、稼働中のサーバーへのファジングは行いません。

| 操作 | 動作 |
| --- | --- |
| 読み取り・検索 | 根拠があり、読み取り操作と分類された場合に自律的に実行します。 |
| 作成・送信・編集・削除 | ウェブサイト、アカウント、操作、確定した入力値を表示し、ユーザーの承認を求めます。 |
| 影響が不明 | リクエストを送信する前に確認が必要です。 |
| 認証・追加確認・リクエスト制限 | 対象のリクエストを一時停止し、再接続または待機できるようにします。 |

承認は特定の1件のリクエストにのみ適用され、5分後に失効し、1回だけ使用できます。入力値、アカウント、保存済みのログイン情報、インストール済みのツール定義が変わると無効になります。CLI、MCP、ダッシュボードからの実行には同じ境界が適用されます。書き込みは自動で再試行しません。

対応範囲はウェブサイトによって異なります。利用できるドキュメントや観測済みの操作がないページでは、ログイン済みのブラウザー、提供されたSiteSpec、追加の準備が必要になる場合があります。Hycliは、すべてのウェブサイトにすぐ使えるAPIがあると主張せず、対応できる範囲を伝えます。

### 対応範囲

JSON・YAMLのOpenAPI、REST、GraphQL、JSON・URLエンコード形式のリクエストに対応します。HTMLでは観測したセレクターから一覧・リンク・次ページ情報を抽出し、必要に応じてローカルのChromiumで描画したGETページを読み取ります。準備中に読み取りが失敗すると、AIが根拠を確認して定義を修正し、再検証します。

任意のブラウザークリック手順、multipartアップロード、バイナリーダウンロードは現在未対応です。アカウントや既存の生成済みCLIは配布物に含まれません。

<a id="ai-connections"></a>
## AI接続

| 接続 | ログイン |
| --- | --- |
| ChatGPT · APIキー | OpenAI APIキー |
| Claude | Anthropic APIキー |
| xAI | xAI APIキー |
| Z.ai | Z.ai APIキー |
| Z.ai Coding Plan | Z.ai Coding Plan APIキー |
| ChatGPT · ログイン | インストール済みのCodex app-serverが管理するChatGPTログイン |

ダッシュボードでモデルを選びます。ご自身のアカウントでのみ利用できるモデルも指定できます。接続チェックではプロバイダーと選択したモデルを検証します。APIの利用料金はプロバイダーのアカウントに請求されます。

Codex接続には公式のapp-serverプロトコルを使用します。HycliはCodexのOAuthトークンを読み取ったりコピーしたりしません。推論は、ファイル、シェル、ブラウザー、アプリケーション、MCPの実行を無効にした一時的なスレッドで行われます。ウェブサイトの準備には、Hycliが制御する読み取りツールを使います。

<a id="use-hycli-with-your-ai"></a>
## AIでHycliを使う

**コーディングエージェント → 接続設定を見る**

通常のMCP接続では、ウェブサイトの準備から実行まで行えます。一度接続すれば、エージェントは不足するツールを準備し、進捗を確認して、新しい操作を実行できます。

```sh
hycli mcp
```

インストール済みの操作だけを公開する場合は `--sites-only` を使います。1つのウェブサイトに限定する接続は次のとおりです。

```sh
hycli mcp --sites-only --only-site SITE
```

```json
{
  "mcpServers": {
    "hycli": {
      "command": "hycli",
      "args": [
        "mcp"
      ]
    }
  }
}
```

エージェントのPATHに `hycli` がない場合は、ダッシュボードに表示された実行ファイルのパスを使ってください。

CLIでも同じ流れを使えます。サンプルURLと `SITE`、`ACTION` を、自分のウェブサイトと `describe` が返した名前に置き換えてください。

```sh
hycli prepare https://your-website.example --intent "保存した参考資料を探す"
hycli request SITE "記事本文の編集、下書き保存、公開機能を追加して"
hycli describe
hycli describe SITE ACTION
hycli SITE ACTION --help
hycli run SITE ACTION --arg query="design systems"
hycli jobs show JOB_ID --watch
```

MCPでは `hycli_prepare` にURLと `intent` を渡し、`hycli_job` または `hycli_result` で完了まで確認します。`hycli_run` は、クライアントがツール一覧を更新する前でも新しい操作を実行できます。内部IDが必要なときは、関連する一覧・検索操作で先に調べます。

変更操作はダッシュボードで確認する承認票を返します。同じ要求を繰り返さず、その結果を確認してください。読み取りの失敗や想定外の応答はCLIでも失敗として扱います。

<a id="browser-sign-in"></a>
## ブラウザーでのログイン

ウェブサイトの準備では、まず現在の OS、実行中または登録済みのブラウザー、利用可能なプロファイルを調べます。AI はその環境で使える機能を選び、ドキュメントの閲覧、ページの表示、サイトのセッションの取り込み、接続の検証を行います。ブラウザーとプロファイルのパスはローカルマシンにとどまり、生成されるウェブサイト定義は開発者のインストールパスに依存しません。

Chrome、Chromium、Edge、Brave、Firefox の Cookie とオリジンストレージは、アクセスできる場合に取り込めます。要求されたウェブサイトのセッションだけが Hycli のローカル保管庫に入ります。Hycli は検証済みの単一の ID を自動的に選びます。同じ ID に属するプロファイルは、アカウント選択時に 1 つの候補として数えられます。既存のアカウント選択は維持されますが、異なる検証済み ID がある場合は選択が必要です。

**アカウント → アカウントを接続**で**ログインを探す**を選ぶと、再検索できます。利用できるセッションが見つからなければ、**ウェブサイトのログイン画面を開く**で既定のブラウザーからサイトを開きます。ダイアログが開いている間はHycliが再確認し、選んだアカウントが検証されてから準備を再開します。タブを開いただけでログイン成功とは表示しません。

OSに保護されたセッション、ブラウザーに紐付いたセッション、プライベートセッション、コンテナー内のセッションでは、ブラウザー拡張機能が必要な場合があります。拡張機能のタブを選んで接続コードを作成し、ログイン済みのプロファイルで拡張機能を開いてコードを入力し、そのウェブサイトへのアクセスを許可してください。標準の取り込みはWindows App-Bound保護を迂回したり、ブラウザープロファイルの保護を弱めたりしません。

- **ChromeとEdge:** パッケージを展開し、ブラウザーの拡張機能ページで**パッケージ化されていない拡張機能を読み込む**を使います。
- **Firefox:** Firefox用パッケージを使い、`about:debugging` で**一時的なアドオンを読み込む**を選びます。Firefoxを再起動すると一時的な拡張機能は削除されます。このリリースには署名済みのストア配布は含まれません。
- **Cookieファイル:** 代替手段としてJSON形式とNetscape形式のCookieファイルをインポートできます。ダッシュボードでファイルを直接インポートし、内容をAIとの会話に貼り付けないでください。

ブラウザーはセッションデータをローカルの認証情報保管庫に直接転送します。モデルが受け取るのはアカウントラベル、ローカルキーの名前と構造、認証情報の値を除いたツール結果です。モデルは値そのものを受け取らずに、ローカルの値を参照する接続手順を作成できます。Cookie の適用範囲、パス、有効期限、対応するパーティション情報が守られ、認証ヘッダーは元のオリジンに限定されます。

アカウントの識別は、ウェブサイトから取得した実際の現在のアカウントの応答に基づきます。ブラウザープロファイル名を、確認済みのウェブサイト上の本人情報として扱いません。まだアカウントを特定できていない場合は、Hycliがその旨を表示します。接続後の通常の閲覧により、リクエストの値、ヘッダー、レスポンス本文を準備用モデルに公開せずに、アカウントの応答や利用可能なリクエストの構造を提供できます。

サイトによっては、別途文書化された API 認証情報や、ローカルでは利用できないブラウザー機能が必要です。準備では実際の接続結果と読み取り結果を記録します。ホームページを取得できたことや API からログインページが返されたことだけでは、連携の準備ができたとは判断しません。[ブラウザー設定ガイド](../../browser-companion/guide.html)で拡張機能の手順と制限を説明しています。

<a id="local-data"></a>
## ローカルデータとリクエスト制限

ウェブサイト定義、アカウントのメタデータ、活動履歴はローカルのデータディレクトリに保存されます。場所を変更するには `HYCLI_DATA_DIR` を設定してください。**設定**で現在の保存先と認証情報の保護状況を確認できます。

利用可能な場合、認証情報保管庫はOSのキーリングで保護された暗号化キーを使用します。キーリングが使えない場合は、ファイルのアクセス権のみで保護される保存方式であることを明示し、非公開ディレクトリと認証情報ファイルへのアクセスを現在のOSユーザーに限定します。既存の暗号化保管庫を解除できない場合でも、通知せずに別の保管庫へ置き換えることはありません。

リクエストはウェブサイトとアカウントごとに順番に処理し、送信間隔を調整します。さらに、ウェブサイト全体にもリクエスト枠を設けます。Hycliは `Retry-After` を尊重し、応答サイズと読み取りの再試行回数を制限し、認証失敗やサイトの追加確認で一時停止します。ウェブサイトの準備では、制限を回避するためのアカウント切り替え、フィンガープリントの偽装、追加確認の迂回は行いません。これらは不要な負荷を減らしますが、ウェブサイトがアカウントを制限しないことを保証するものではありません。

プライベートおよびローカルのウェブサイトアドレスは、既定では無効です。信頼できる自己ホスト型サイトを使う場合は、ダッシュボードまたはMCPサーバーの起動時に `--allow-local` を明示してください。

<a id="contributing"></a>
## 開発と検証

```sh
npm --prefix dashboard ci
npm --prefix dashboard run check
npm --prefix dashboard run build
cargo test --all-targets --locked
cargo build --locked --bin hycli --example dashboard_fixture
node scripts/test-e2e.mjs --full
```

テストには、合成したローカルのウェブサイトとプロバイダー応答を使います。承認とリクエストの結び付け、再利用の防止、秘密情報の除去、リダイレクト、レート制限、書き込みの再試行禁止、ブラウザーセッションの保護、プロバイダー応答の契約を検証します。Hycliのテストだけを目的に、実際のアカウントでコンテンツを作成、変更、削除しないでください。

スクリーンショットと GIF には独立したサンプルデータを使用しています。[画像の出典](../images/README.md)をご覧ください。
