<a id="try-it-in-30-seconds"></a>
## Попробовать за 30 секунд

```sh
# 1. Укажите Hycli сайт и опишите цель (подготавливает чтение и запись; 0 реальных изменений при настройке)
hycli prepare https://your-website.example --intent "Искать публикации, сохранять черновики и публиковать статьи"

# 2. Посмотрите все подготовленные команды чтения, записи и многошаговые сценарии
hycli describe your-website

# 3. Сразу выполняйте операции чтения и поиска
hycli your-website search-posts --query "примечания к выпуску"

# 4. Включите запись один раз для этого CLI, когда будете готовы создавать, редактировать или удалять
hycli writes your-website allow
hycli your-website create-draft --title "Привет из Hycli" --body "Автоматизировано прямо из терминала."
```

Или подключите Hycli к **Claude Code, Cursor, Codex или Windsurf** один раз с помощью `"command": "hycli", "args": ["mcp"]` и попросите агента на обычном языке:
> *«Используй Hycli, чтобы подготовить `https://...`, покажи мне доступные действия и создай черновик новой публикации».*

<a id="get-started"></a>
## Начало работы

Hycli поставляется в виде единого нативного бинарного файла, включающего как движок работы с сайтами, так и локальную панель управления (`http://127.0.0.1:4318`). Для запуска релизного пакета не требуются ни Rust, ни Node.js.

### Скачивание и запуск (Windows, macOS, Linux)

Скачайте нативный установщик или портативный архив для вашей платформы на странице **[GitHub Releases (v0.1.0)](https://github.com/Hybirdss/Hycli/releases/tag/v0.1.0)**:

| Платформа | Архитектура | Нативный установщик | Портативный архив | Как запустить |
| --- | --- | --- | --- | --- |
| **Windows 10/11** | x64 и ARM64 | `hycli-0.1.0-win32-*-setup.exe` | `hycli-0.1.0-win32-*.tar.gz` | Запустите `*-setup.exe` (добавит `hycli` в пользовательский `PATH` и меню «Пуск»), затем откройте **Hycli** или выполните `hycli open` в PowerShell. |
| **macOS 13+** | Apple Silicon (`arm64`) и Intel (`x64`) | `hycli-0.1.0-darwin-*.dmg` | `hycli-0.1.0-darwin-*.tar.gz` | Откройте `.dmg`, перетащите **Hycli.app** в **Applications** и запустите приложение (автоматически связывает `hycli` в `~/.local/bin`). |
| **Linux** | x64 и ARM64 | `hycli-0.1.0-linux-*.deb` | `hycli-0.1.0-linux-*.tar.gz` | Установите `.deb` (`sudo apt install ./hycli-*.deb`) или распакуйте `.tar.gz` и запустите `./install.sh`, затем выполните `hycli open`. |

### Подключите свой первый сайт

1. Выполните `hycli open` (или нажмите на значок приложения **Hycli**), чтобы открыть локальную панель управления по адресу `http://127.0.0.1:4318`.
2. Откройте **Подключения к ИИ** и подключите OpenAI, Anthropic Claude, xAI, Z.ai или локальный вход ChatGPT (Codex).
3. Для сайтов с авторизацией нажмите **Аккаунты → Найти мой вход**, чтобы импортировать сессию браузера в локальное зашифрованное хранилище.
4. Введите URL сайта и (необязательно) цель или скопируйте конфигурацию MCP из раздела **Агенты программирования** в вашего ИИ-помощника.

<a id="what-your-ai-can-do"></a>
## Что может ваш ИИ

Hycli превращает реальные интерфейсы веб-сайтов в самодокументируемые подкоманды CLI и инструменты MCP:

| Интерфейс веб-сайта | Подготавливаемая возможность |
| --- | --- |
| REST и OpenAPI | Типизированные действия чтения и записи на основе схем JSON/YAML и документации API. |
| GraphQL | Разобранные документы запросов (`query`) и мутаций (`mutation`) с типизированными JSON-переменными. |
| HTML и страницы с JS-рендерингом | Структурированные записи, ссылки, пагинация и чтение GET-страниц с рендерингом через локальный движок Chromium. |
| JSON-формы и URL-кодированные формы | Документированные входные поля, значения по умолчанию и отправка форм в контексте аккаунта (`POST`, `PUT`, `PATCH`, `DELETE`). |

| Тип действия | Поведение при выполнении |
| --- | --- |
| **Чтение или поиск** | Выполняется сразу, когда подтверждено данными и классифицировано как безопасное чтение. |
| **Создание, отправка, изменение или удаление** | Обнаруживается и включается в спецификацию CLI, но никогда не запускается во время подготовки. По умолчанию отключено (`writes: false`). ИИ-агент спрашивает вас **один раз для каждого CLI**, разрешить ли запись (`hycli writes SITE allow` или MCP `hycli_writes`). После включения операции записи выполняются напрямую по вашему запросу. |
| **Неясный эффект** | Удерживается для проверки перед отправкой. |
| **Проверка авторизации или лимит запросов** | Переключает стратегию транспорта (HTTP → внутристраничный `window.fetch` → скрытый Chromium) или аккуратно ставит выполнение на паузу. |

Поддерживаемые форматы запросов и правила извлечения данных описаны в [спецификации операций](../SITESPEC.md).

<a id="common-concerns"></a>
## Частые опасения и как Hycli их решает

Подключение ИИ-агента к реальным веб-сайтам и авторизованным аккаунтам вызывает серьёзные вопросы. Вот как Hycli решает каждый из них на уровне архитектуры:

### 1. «Не сможет ли ИИ случайно опубликовать, изменить или удалить данные в моём аккаунте?»
- **Ноль реальных изменений при создании CLI:** Во время подготовки или проверки сайта (`hycli prepare`, `hycli request`, `hycli recon`, `hycli check`) Hycli обнаруживает и компилирует в спецификацию CLI как чтение, так и запись, но **никогда не выполняет запросы на запись**. Даже замаскированные мутации (`GET`-маршруты с изменяющими путями вроде `/delete`, тела GraphQL `mutation` или отправка HTML `<form method="post">`) блокируются при проверке.
- **Однократное подтверждение записи для каждого CLI:** Каждый новый CLI сайта создаётся с `writes: false`. Когда ИИ-агенту впервые нужно выполнить действие записи в этом CLI, он спрашивает вас **один раз для данного CLI**: *«Разрешить действия записи для `<site>`?»* Только после вашего согласия выполняется `hycli writes <site> allow` (или MCP `hycli_writes`), открывая прямое выполнение записи для этого CLI. Вы можете отозвать разрешение в любой момент командой `hycli writes <site> deny` или переключателем **Разрешить изменения** в панели управления.
- **Никаких автоматических повторов записи:** Неудачные или прерванные запросы на запись никогда не повторяются автоматически. Если соединение обрывается после отправки мутации, Hycli возвращает `action_outcome_unknown`, чтобы вы могли проверить сайт, а не создать дубликат заказа или поста.

### 2. «Отправляет ли Hycli мои cookie, токены входа или API-ключи в ИИ-модель?»
- **Секреты никогда не попадают в промпты LLM:** Cookie браузера, токены `localStorage` / `sessionStorage` и API-ключи хранятся строго в вашем локальном зашифрованном хранилище (защищённом системной связкой ключей в диспетчере учётных данных Windows, связке ключей macOS и Linux Secret Service либо правами доступа `0600` только для владельца).
- **Символические рецепты подключения (`ConnectionRecipe`):** ИИ-модели видят только метки аккаунтов, имена ключей хранилища и отредактированные схемы ответов. Модель строит символический `ConnectionRecipe` (ссылаясь лишь на имя cookie или токена), а Hycli локально подставляет реальный секрет в момент выполнения и очищает секреты из всех выходных данных и логов.
- **Импорт только для чтения в рамках одного домена:** Импорт сессии браузера считывает cookie и данные хранилища только целевого домена из временного снимка в режиме чтения. Он никогда не ослабляет защиту браузера и не экспортирует данные других сайтов.

### 3. «Не приведёт ли работа с сайтом к появлению CAPTCHA или блокировке аккаунта?»
- **Никакого фаззинга и перебора эндпоинтов:** Hycli никогда не угадывает списки URL и не фаззит живые серверы. Он обучается только по связанной документации, схемам OpenAPI/GraphQL, статическим JS-бандлам и наблюдаемой структуре сетевых запросов браузера.
- **Последовательный трафик с контролем частоты:** Запросы выполняются последовательно и ограничиваются по скорости для каждого сайта и аккаунта с соблюдением заголовка `Retry-After` и строгими лимитами на повторы чтения.
- **Автоматический предохранитель стратегий и выполнение в контексте реального браузера:** Когда обычный HTTP-запрос сталкивается с кодом 403/429 или антибот-проверкой (Cloudflare, Akamai Bot Manager), Hycli не зацикливает заблокированный запрос. Предохранитель мгновенно переключает транспорт — выполняя `window.fetch(..., { credentials: 'include' })` внутри вашего авторизованного контекста браузера или используя локальный движок скрытого Chromium — либо безопасно приостанавливает работу для защиты аккаунта.

### 4. «Может ли редирект привести к утечке сессии, а опубликованная спецификация — раскрыть пути на моём компьютере?»
- **Строгая привязка к источнику (Origin):** Заголовки авторизации и cookie жёстко привязаны к целевому источнику и немедленно удаляются при междоменных перенаправлениях. Частные и локальные диапазоны IP-адресов по умолчанию заблокированы, если явно не указан флаг `--allow-local`.
- **Переносимые спецификации:** Локальные пути к исполняемым файлам и профилям браузеров остаются только во внутреннем состоянии устройства и никогда не записываются в переносимые файлы `SiteSpec`.

### 5. «Будет ли ИИ впустую тратить токены на повторные попытки, когда истечёт срок действия входа?»
- **Детерминированная проверка состояния без ИИ (`hycli check`):** Команда `hycli check` (и MCP `hycli_check`) воспроизводит проверенные цепочки чтения без вызова LLM и чётко отделяет `signed_out` (переподключите аккаунт) от `site_changed` (обновите спецификацию), `blocked` и `unreachable`.

<a id="use-hycli-with-your-ai"></a>
## Использование Hycli с вашим ИИ

Добавьте Hycli в ваш MCP-клиент (**Агенты программирования → Показать настройки подключения** отображает точный путь для вашей ОС):

```json
{
  "mcpServers": {
    "hycli": {
      "command": "hycli",
      "args": ["mcp"]
    }
  }
}
```

Используйте `hycli mcp --sites-only`, чтобы открыть доступ только к установленным инструментам сайтов, или добавьте `--only-site SITE`, чтобы ограничить доступ одним сайтом. MCP-сервер предоставляет `hycli_prepare`, `hycli_writes` (включает запись один раз для каждого CLI после вашего подтверждения), `hycli_run`, `hycli_check`, `hycli_result` и `hycli_activity` — и никогда не предоставляет инструмент для чтения учётных данных.

Из терминала все рабочие процессы выполняются точно так же:

```sh
hycli prepare https://your-website.example --intent "Найти сохранённые материалы"
hycli request SITE "Добавь редактирование черновиков и публикацию с полным текстом поста"
hycli describe SITE
hycli SITE ACTION --help
hycli writes SITE allow
hycli SITE ACTION --query "design systems"
hycli check SITE
```

<a id="browser-sign-in"></a>
## Вход через браузер

Hycli обнаруживает локальные профили Chrome, Chromium, Edge, Brave, Vivaldi, Arc, Whale и Firefox (а также установленный локальный скрытый Chromium) в Windows, macOS и Linux, импортируя в локальное зашифрованное хранилище только сессию запрошенного сайта. Профили, использующие один и тот же подтверждённый аккаунт на сайте, автоматически объединяются.

Если сессия защищена шифрованием Windows App-Bound, изолированными контейнерами или находится в неимпортированном браузере, используйте **Аккаунты → Подключить аккаунт**, чтобы войти через браузер, подключите [расширение-компаньон для браузера](../../browser-companion/guide.html) или импортируйте файл cookie в формате JSON/Netscape в панели управления (никогда не вставляйте содержимое cookie в чат с ИИ).

## Локальные данные и лимиты запросов

Определения сайтов, зашифрованные учётные данные и журнал активности хранятся в системном каталоге данных вашей ОС (`%LOCALAPPDATA%\hycli` в Windows, `~/Library/Application Support/hycli` в macOS, `~/.local/share/hycli` в Linux или `HYCLI_DATA_DIR`). Проверить активный режим защиты хранилища можно в любой момент в разделе **Настройки**.
