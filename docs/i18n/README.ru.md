<a id="get-started"></a>
Введите домен и при желании укажите цель рядом. Сначала ИИ изучает сайт и выбирает полезные задачи, затем проверяет необходимые условия, данные и результаты. Если каких-то шагов не хватает, сайт остаётся помеченным для проверки.

## Начало работы

**[Скачать v0.1.0 · Linux x64](https://github.com/Hybirdss/Hycli/releases/tag/v0.1.0)** · glibc ≥ 2.39 · [SHA-256](https://github.com/Hybirdss/Hycli/releases/download/v0.1.0/hycli-0.1.0-linux-x64.tar.gz.sha256)

Hycli — приложение на Rust с локальной веб-панелью. В этой копии репозитория соберите панель и исполняемый файл:

```sh
node scripts/build.mjs
./dist/hycli dashboard
```

Панель открывается по адресу `http://127.0.0.1:4318`. Команда `hycli dashboard --no-open` выводит адрес, не открывая браузер. Параметр `--port 4320` позволяет выбрать другой порт. Движок сайтов и панель входят в один исполняемый файл.

1. Откройте **Подключения ИИ** и подключите провайдера.
2. Добавьте адрес сайта и выберите ИИ для его подготовки.
3. Просмотрите доступные действия. Запустите одно из них на панели или откройте **Агенты для программирования**, чтобы один раз скопировать конфигурацию MCP.

Если на сайте нужен вход, подключите аккаунт в разделе **Аккаунты**. Для одного сайта можно сохранить несколько аккаунтов и выбрать тот, который будут использовать его инструменты.

<a id="what-your-ai-can-do"></a>
## Что может ваш ИИ

Hycli превращает поддерживаемые операции сайта в инструменты с именами и заданными типами данных. Описания, написанные ИИ, объясняют, что делает каждое действие, какие сведения ему нужны и что оно возвращает.

Три независимых агента ИИ занимаются чтением и поиском, полезными сценариями работы и сведениями об аккаунте. Панель показывает завершённые этапы, состояние каждого агента, прошедшее время и понятные заметки о работе. Действия CLI и MCP отображаются в той же истории активности.

Подготовка опирается на сведения, действительно доступные на сайте: документацию по ссылкам, схемы API, опубликованный JavaScript и структуры запросов, наблюдаемые расширением браузера. Для проверки операции могут выполняться ограниченные запросы на чтение. При подготовке не создаются тестовые записи, не редактируется содержимое, не удаляются объекты, не угадываются большие списки адресов API и не отправляются случайные тестовые данные на работающий сервер.

| Действие | Поведение |
| --- | --- |
| Чтение или поиск | Выполняется самостоятельно, если операция подтверждена имеющимися данными и классифицирована как чтение. |
| Создание, отправка, редактирование или удаление | Показывает сайт, аккаунт, действие и окончательные входные данные для одобрения пользователем. |
| Неясный эффект | Требует проверки перед отправкой запроса. |
| Аутентификация, дополнительная проверка или лимит запросов | Приостанавливает затронутые запросы и позволяет подключиться снова или подождать. |

Одобрение относится к одному конкретному запросу, действует пять минут и может быть использовано только один раз. Изменение входных данных, аккаунта, сохранённых данных входа или установленного определения инструмента аннулирует его. Это правило одинаково действует в CLI, MCP и на панели. Запросы, изменяющие данные, никогда не повторяются автоматически.

Поддержка зависит от сайта. Странице без подходящей документации или наблюдаемых операций может понадобиться браузер с выполненным входом, предоставленный SiteSpec или дополнительная подготовка. Hycli сообщает, что может поддержать, и не предполагает, что у каждого сайта есть готовый API.

### Поддерживаемые возможности

Поддерживаются OpenAPI в JSON или YAML, REST, GraphQL, JSON-запросы и формы с URL-кодированием. Записи, ссылки и следующая страница извлекаются из HTML по наблюдаемым селекторам; также доступны GET-страницы, отрисованные локальным Chromium. Если чтение при подготовке не удалось, ИИ анализирует данные, исправляет определение и проверяет его снова.

Произвольные последовательности кликов, multipart-загрузка и скачивание двоичных файлов пока не реализованы. Пакеты не содержат аккаунтов или ранее созданных CLI.

<a id="ai-connections"></a>
## Подключения ИИ

| Подключение | Вход |
| --- | --- |
| ChatGPT · API key | Ваш ключ API OpenAI |
| Claude | Ваш ключ API Anthropic |
| xAI | Ваш ключ API xAI |
| Z.ai | Ваш ключ API Z.ai |
| Z.ai Coding Plan | Ваш ключ API Z.ai Coding Plan |
| ChatGPT · login | Вход через ChatGPT, которым управляет установленный Codex app-server |

Выберите модель на панели, в том числе модель, доступную специально вашему аккаунту. При проверке соединения проверяются провайдер и выбранная модель. Провайдеры API списывают оплату за использование с вашего аккаунта у провайдера.

Подключение Codex использует официальный протокол app-server. Hycli не читает и не копирует токены OAuth Codex. Модель работает во временном потоке с отключённым выполнением операций через файлы, оболочку, браузер, приложения и MCP. Подготовка сайтов выполняется контролируемыми инструментами чтения Hycli.

<a id="use-hycli-with-your-ai"></a>
## Используйте Hycli с вашим ИИ

**Агенты для программирования → Посмотреть настройки подключения**

Общее подключение MCP позволяет подготавливать сайты и выполнять действия. Подключите агента один раз, чтобы он мог создавать недостающие инструменты, следить за ходом работы и использовать новые действия.

```sh
hycli mcp
```

Параметр `--sites-only` открывает только установленные действия. Следующее подключение ограничено одним сайтом.

```sh
hycli mcp --sites-only --only-site SITE
```

```json
{
  "mcpServers": {
    "hycli": {
      "command": "hycli",
      "args": [
        "mcp"
      ]
    }
  }
}
```

Если `hycli` отсутствует в PATH агента, используйте путь к исполняемому файлу из панели.

Тот же процесс доступен в CLI. Замените пример URL, `SITE` и `ACTION` своим сайтом и именами, которые возвращает `describe`.

```sh
hycli prepare https://your-website.example --intent "Найти сохранённые материалы"
hycli request SITE "Add draft editing and publishing with full post content"
hycli describe
hycli describe SITE ACTION
hycli SITE ACTION --help
hycli run SITE ACTION --arg query="design systems"
hycli jobs show JOB_ID --watch
```

В MCP передайте URL и `intent` в `hycli_prepare`, затем следите за задачей через `hycli_job` или `hycli_result`. `hycli_run` выполняет новые действия, даже если клиент ещё не обновил список инструментов. Внутренние идентификаторы сначала ищите через связанные действия просмотра списков или поиска.

Действия с изменениями возвращают квитанцию для проверки в панели. Следите за её результатом, не повторяя запрос. Неудачное чтение или неожиданный ответ также приводят к ошибке CLI.

<a id="browser-sign-in"></a>
## Вход через браузер

Подготовка сайта начинается с проверки текущей ОС, работающих и зарегистрированных браузеров и доступных профилей. ИИ выбирает из этих возможностей средства для чтения документации, отображения страниц, импорта сеанса сайта и проверки подключения. Пути к браузерам и профилям остаются на локальном компьютере; создаваемое определение сайта не зависит от путей установки разработчика.

Файлы cookie и хранилище источника из Chrome, Chromium, Edge, Brave и Firefox можно импортировать, если они доступны. В локальное хранилище Hycli попадает только сеанс запрошенного сайта. Hycli автоматически выбирает одну подтверждённую личность; профили этой же личности считаются одним вариантом при выборе учётной записи. Ранее выбранная учётная запись сохраняется; если подтверждены разные личности, требуется выбор.

В разделе **Аккаунты → Подключить аккаунт** кнопка **Найти мой вход** повторяет поиск. Если подходящий сеанс не найден, **Открыть страницу входа на сайт** открывает сайт в браузере по умолчанию. Пока окно открыто, Hycli проверяет вход повторно и продолжает подготовку только после подтверждения выбранного аккаунта. Само открытие вкладки не означает успешного входа.

Для сеансов, защищённых ОС, привязанных к браузеру, приватных или изолированных в контейнере может потребоваться расширение. Выберите вкладку расширения и создайте код подключения, затем откройте расширение в профиле с выполненным входом, введите код и разрешите доступ к сайту. Прямой импорт не обходит защиту Windows App-Bound и не ослабляет профиль браузера.

- **Chrome и Edge:** распакуйте архив и выберите **Загрузить распакованное расширение** на странице расширений браузера.
- **Firefox:** используйте пакет для Firefox и **Загрузить временное дополнение** на странице `about:debugging`. Временные расширения удаляются при перезапуске Firefox. В этой версии нет распространения подписанного расширения через магазин.
- **Файл cookies:** в качестве запасного варианта доступен импорт файлов cookies в форматах JSON и Netscape. Импортируйте файл прямо на панели; не вставляйте его содержимое в разговор с ИИ.

Браузер передаёт данные сеанса непосредственно в локальное хранилище учётных данных. Модели получают метки учётных записей, имена и структуру локальных ключей, а также результаты инструментов без значений учётных данных. Они могут составить рецепт подключения со ссылками на эти локальные значения, не получая сами значения. Соблюдаются область действия, пути, срок действия и поддерживаемые сведения о разделении файлов cookie; заголовки аутентификации ограничены исходным источником.

Аккаунт определяется по реальному ответу сайта о текущем аккаунте. Имя профиля браузера не считается подтверждённой личностью на сайте. Если аккаунт ещё не определён, Hycli сообщает об этом. После подключения обычный просмотр сайта может предоставить ответ с данными аккаунта и структуры доступных запросов. Значения запросов, заголовки и тела ответов не раскрываются модели, которая готовит инструменты.

Сайту могут потребоваться отдельные документированные учётные данные API или возможность браузера, недоступная локально. При подготовке записываются фактические результаты подключения и чтения. Загрузка главной страницы или получение страницы входа от API не означает, что интеграция готова. [Руководство по настройке браузера](../../browser-companion/guide.html) описывает работу расширения и ограничения.

<a id="local-data"></a>
## Локальные данные и лимиты запросов

Определения сайтов, метаданные аккаунтов и история остаются в локальном каталоге данных. Задайте `HYCLI_DATA_DIR`, чтобы выбрать другое расположение. В **Настройках** можно посмотреть текущий путь и способ защиты учётных данных.

При наличии системного хранилища ключей оно защищает ключ шифрования хранилища учётных данных. Если системное хранилище недоступно, Hycli явно сообщает, что защита основана только на правах доступа к файлам. Приватные каталоги и файлы учётных данных доступны только текущему пользователю ОС. Если существующее зашифрованное хранилище нельзя разблокировать, оно не заменяется незаметно.

Запросы выполняются последовательно и с паузами для каждого сайта и аккаунта; дополнительно действует общий лимит сайта. Hycli учитывает `Retry-After`, ограничивает размеры ответов и число повторов чтения, приостанавливает работу при ошибках аутентификации или дополнительных проверках сайта. При подготовке сайта Hycli не меняет аккаунты, не подделывает цифровые отпечатки и не обходит проверки; диагностическое поведение движка может отличаться. Эти меры снижают лишнюю нагрузку, но не гарантируют, что сайт никогда не ограничит аккаунт.

Приватные и локальные адреса сайтов по умолчанию отключены. Для доверенного сайта на собственном сервере явно запустите панель или сервер MCP с `--allow-local`.

<a id="contributing"></a>
## Разработка и проверка

```sh
npm --prefix dashboard ci
npm --prefix dashboard run check
npm --prefix dashboard run build
cargo test --all-targets --locked
cargo build --locked --bin hycli --example dashboard_fixture
node scripts/test-e2e.mjs --full
```

Тесты используют искусственные локальные сайты и ответы провайдеров. Они проверяют привязку одобрения и защиту от повторного использования, удаление секретных данных, перенаправления, лимиты запросов, отсутствие повторов записи, защиту сеансов браузера и соответствие ответов провайдеров ожидаемому формату. Никогда не создавайте, не изменяйте и не удаляйте содержимое в реальном аккаунте только ради проверки Hycli.

Скриншоты и GIF используют изолированные демонстрационные данные. См. [источники изображений](../images/README.md).
