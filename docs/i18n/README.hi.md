डोमेन दर्ज करें और चाहें तो बगल में उद्देश्य लिखें। AI पहले वेबसाइट को समझकर उपयोगी कार्य चुनता है, फिर पूर्वापेक्षाओं, इनपुट और अंतिम परिणामों की जाँच करता है। कोई चरण अधूरा होने पर वेबसाइट समीक्षा के लिए चिह्नित रहती है।

## शुरुआत करें

**[डाउनलोड v0.1.0 · Linux x64](https://github.com/Hybirdss/Hycli/releases/tag/v0.1.0)** · glibc ≥ 2.39 · [SHA-256](https://github.com/Hybirdss/Hycli/releases/download/v0.1.0/hycli-0.1.0-linux-x64.tar.gz.sha256)

Hycli एक Rust ऐप है जिसका वेब डैशबोर्ड आपके डिवाइस पर चलता है। रिपॉज़िटरी की इस कॉपी से डैशबोर्ड और प्रोग्राम बिल्ड करें:

```sh
node scripts/build.mjs
./dist/hycli dashboard
```

डैशबोर्ड `http://127.0.0.1:4318` पर खुलता है। ब्राउज़र खोले बिना पता दिखाने के लिए `hycli dashboard --no-open` इस्तेमाल करें। दूसरा पोर्ट चुनने के लिए `--port 4320` दें। वेबसाइट का इंजन और डैशबोर्ड एक ही प्रोग्राम में शामिल हैं।

1. **AI कनेक्शन** खोलें और सेवा जोड़ें।
2. वेबसाइट का पता जोड़ें और उसे तैयार करने वाला AI चुनें।
3. उपलब्ध काम देखें। कोई काम डैशबोर्ड में चलाएँ या MCP कॉन्फ़िगरेशन एक बार कॉपी करने के लिए **कोडिंग एजेंट** खोलें।

लॉगिन वाली वेबसाइट के लिए **खाते** से उसका खाता जोड़ें। एक वेबसाइट के कई खाते सहेजे जा सकते हैं; उसके टूल कौन-सा खाता इस्तेमाल करें, यह आप चुनते हैं।

<a id="what-your-ai-can-do"></a>
## आपका AI क्या कर सकता है

Hycli वेबसाइट के समर्थित कामों को नाम और तय डेटा प्रकार वाले टूल में बदलता है। AI के लिखे विवरण बताते हैं कि हर काम क्या करता है, उसे कौन-सी जानकारी चाहिए और वह क्या नतीजा देता है।

तीन स्वतंत्र AI एजेंट पढ़ने और खोजने, उपयोगी कार्य प्रक्रियाओं और खाते से जुड़े प्रमाण पर काम करते हैं। डैशबोर्ड में पूरी हुई अवस्थाएँ, हर एजेंट की स्थिति, बीता समय और सरल भाषा में कार्य नोट दिखते हैं। CLI और MCP के काम भी इसी गतिविधि इतिहास में दिखाई देते हैं।

<p align="center">
  <img src="../../docs/images/preparation.gif" alt="तीन वर्कर। एक नन्ही-सी चिड़िया, बहुत व्यस्त।" width="100%" />
</p>
<p align="center"><sub>तीन वर्कर। एक नन्ही-सी चिड़िया, बहुत व्यस्त।</sub></p>

तैयारी वेबसाइट से सचमुच उपलब्ध जानकारी पर आधारित होती है: उससे जुड़े दस्तावेज़, API स्कीमा, प्रकाशित JavaScript और ब्राउज़र एक्सटेंशन में देखे गए अनुरोधों की संरचना। किसी काम की जाँच के लिए सीमित दायरे में जानकारी पढ़ी जा सकती है। तैयारी के दौरान टेस्ट रिकॉर्ड बनाना, सामग्री बदलना, चीज़ें मिटाना, API के पते की लंबी सूचियाँ अंदाज़े से बनाना या चालू सर्वर पर बेतरतीब टेस्ट डेटा भेजना शामिल नहीं है।

| काम | व्यवहार |
| --- | --- |
| पढ़ना या खोजना | अगर उपलब्ध प्रमाण काम का समर्थन करते हैं और उसे जानकारी पढ़ने वाला काम माना गया है, तो वह अपने आप चलता है। |
| बनाना, भेजना, बदलना या मिटाना | वेबसाइट, खाता, काम और तय इनपुट दिखाकर उपयोगकर्ता की मंज़ूरी माँगी जाती है। |
| असर स्पष्ट न होना | अनुरोध भेजने से पहले समीक्षा ज़रूरी है। |
| लॉगिन, अतिरिक्त जाँच या अनुरोध की सीमा | संबंधित अनुरोध रोक दिए जाते हैं और आप दोबारा जुड़ सकते हैं या इंतज़ार कर सकते हैं। |

मंज़ूरी एक निश्चित अनुरोध के लिए होती है, पाँच मिनट में समाप्त हो जाती है और सिर्फ़ एक बार इस्तेमाल हो सकती है। इनपुट, खाता, सहेजी गई लॉगिन जानकारी या इंस्टॉल किए गए टूल की परिभाषा बदलने पर मंज़ूरी अमान्य हो जाती है। CLI, MCP और डैशबोर्ड में यही सीमा लागू होती है। बदलाव करने वाले अनुरोध कभी अपने आप दोबारा नहीं चलाए जाते।

समर्थन वेबसाइट पर निर्भर करता है। जिस पेज के उपयोगी दस्तावेज़ या देखे गए काम उपलब्ध नहीं हैं, उसके लिए लॉगिन किया हुआ ब्राउज़र, दिया गया SiteSpec या और तैयारी चाहिए हो सकती है। Hycli बताता है कि वह क्या सँभाल सकता है; वह यह दावा नहीं करता कि हर वेबसाइट का तैयार API है।

### समर्थित क्षमताएँ

JSON या YAML OpenAPI, REST, GraphQL और JSON या URL-एन्कोड किए गए फ़ॉर्म अनुरोध समर्थित हैं। देखे गए चयनकर्ताओं से HTML रिकॉर्ड, लिंक और अगले पन्ने की जानकारी निकाली जा सकती है; स्थानीय Chromium से रेंडर किए गए GET पन्ने भी पढ़े जा सकते हैं। तैयारी के दौरान पढ़ने में विफलता हो, तो AI साक्ष्य देखता है, परिभाषा सुधारता है और फिर जाँचता है।

मनचाहे ब्राउज़र क्लिक क्रम, multipart अपलोड और बाइनरी डाउनलोड अभी समर्थित नहीं हैं। पैकेज में खाते या पहले से बनाई गई CLI शामिल नहीं होतीं।

## AI कनेक्शन

| कनेक्शन | लॉगिन |
| --- | --- |
| ChatGPT · API key | आपकी OpenAI API कुंजी |
| Claude | आपकी Anthropic API कुंजी |
| xAI | आपकी xAI API कुंजी |
| Z.ai | आपकी Z.ai API कुंजी |
| Z.ai Coding Plan | आपकी Z.ai Coding Plan API कुंजी |
| ChatGPT · login | इंस्टॉल किए गए Codex app-server से प्रबंधित ChatGPT लॉगिन |

डैशबोर्ड में मॉडल चुनें। आपके खाते के लिए खास तौर पर उपलब्ध मॉडल भी चुन सकते हैं। कनेक्शन की जाँच सेवा और चुने गए मॉडल को सत्यापित करती है। API सेवाएँ इस्तेमाल की फ़ीस आपके सेवा खाते पर लगाती हैं।

Codex कनेक्शन उसके आधिकारिक app-server प्रोटोकॉल का इस्तेमाल करता है। Hycli, Codex के OAuth टोकन पढ़ता या कॉपी नहीं करता। मॉडल एक अस्थायी बातचीत में चलता है, जिसमें फ़ाइल, शेल, ब्राउज़र, ऐप और MCP के ज़रिए काम चलाने की अनुमति बंद रहती है। वेबसाइट की तैयारी Hycli के नियंत्रित रीड टूल करते हैं।

<a id="use-hycli-with-your-ai"></a>
## Hycli को अपने AI के साथ इस्तेमाल करें

**कोडिंग एजेंट → कनेक्शन सेटिंग्स देखें**

सामान्य MCP कनेक्शन वेबसाइट तैयार करने और कार्रवाइयाँ चलाने, दोनों के लिए है। एजेंट को एक बार जोड़ें, ताकि वह ज़रूरी नए टूल तैयार कर सके, प्रगति देख सके और नई कार्रवाइयाँ चला सके।

```sh
hycli mcp
```

केवल इंस्टॉल की गई कार्रवाइयाँ उपलब्ध कराने के लिए `--sites-only` इस्तेमाल करें। नीचे दिया गया कनेक्शन एक वेबसाइट तक सीमित है।

```sh
hycli mcp --sites-only --only-site SITE
```

```json
{
  "mcpServers": {
    "hycli": {
      "command": "hycli",
      "args": [
        "mcp"
      ]
    }
  }
}
```

अगर एजेंट के PATH में `hycli` नहीं है, तो डैशबोर्ड में दिखाया गया प्रोग्राम पथ इस्तेमाल करें।

यही प्रक्रिया CLI में भी उपलब्ध है। उदाहरण URL, `SITE` और `ACTION` की जगह अपनी वेबसाइट और `describe` से मिले नाम डालें।

```sh
hycli prepare https://your-website.example --intent "सहेजे गए संदर्भ खोजें"
hycli request SITE "Add draft editing and publishing with full post content"
hycli describe
hycli describe SITE ACTION
hycli SITE ACTION --help
hycli run SITE ACTION --arg query="design systems"
hycli jobs show JOB_ID --watch
```

MCP में URL और `intent` को `hycli_prepare` में दें, फिर `hycli_job` या `hycli_result` से काम पूरा होने तक स्थिति देखें। क्लाइंट की टूल सूची अपडेट होने से पहले भी `hycli_run` नई कार्रवाइयाँ चला सकता है। आंतरिक ID के लिए पहले संबंधित सूची या खोज वाली कार्रवाइयाँ इस्तेमाल करें।

बदलाव वाली कार्रवाई डैशबोर्ड में समीक्षा के लिए एक रसीद देती है। अनुरोध दोहराने के बजाय उसी का परिणाम देखें। पढ़ने में विफलता या अप्रत्याशित जवाब होने पर CLI भी विफलता बताती है।

## ब्राउज़र से लॉगिन

वेबसाइट की तैयारी मौजूदा ऑपरेटिंग सिस्टम, चल रहे और पंजीकृत ब्राउज़र तथा उपलब्ध प्रोफ़ाइल की जाँच से शुरू होती है। AI इन उपलब्ध क्षमताओं के आधार पर दस्तावेज़ पढ़ता है, पेज दिखाता है, वेबसाइट का सत्र इम्पोर्ट करता है और कनेक्शन सत्यापित करता है। ब्राउज़र और प्रोफ़ाइल के पाथ स्थानीय मशीन पर ही रहते हैं; बनाई गई वेबसाइट की परिभाषा डेवलपर के इंस्टॉलेशन पाथ पर निर्भर नहीं करती।

Chrome, Chromium, Edge, Brave और Firefox की कुकी और मूल साइट का संग्रहण उपलब्ध होने पर इम्पोर्ट किए जा सकते हैं। केवल अनुरोध की गई वेबसाइट का सत्र Hycli के स्थानीय वॉल्ट में जाता है। Hycli अपने आप एक सत्यापित पहचान चुनता है; उसी पहचान वाली प्रोफ़ाइल खाता चुनते समय एक ही विकल्प मानी जाती हैं। पहले चुना गया खाता बना रहता है; अलग-अलग सत्यापित पहचान मिलने पर चुनाव करना पड़ता है।

**खाते → खाता जोड़ें** में **मेरा साइन-इन खोजें** उस खोज को दोहराता है। उपयोगी सत्र न मिलने पर **वेबसाइट का साइन-इन पेज खोलें** वेबसाइट को आपके डिफ़ॉल्ट ब्राउज़र में खोलता है। संवाद खुला रहने तक Hycli दोबारा जाँचता है और चुने गए खाते की पुष्टि होने पर ही तैयारी जारी रखता है। सिर्फ़ टैब खुलना सफल लॉगिन का प्रमाण नहीं है।

ऑपरेटिंग सिस्टम से सुरक्षित, ब्राउज़र से जुड़े, निजी या कंटेनर सत्रों के लिए ब्राउज़र कंपैनियन की ज़रूरत पड़ सकती है। कंपैनियन टैब चुनकर कनेक्शन कोड बनाएँ। फिर लॉगिन वाली प्रोफ़ाइल में कंपैनियन खोलें, कोड डालें और उस वेबसाइट का ऐक्सेस दें। सीधे इम्पोर्ट से Windows App-Bound सुरक्षा बायपास नहीं होती और ब्राउज़र प्रोफ़ाइल की सुरक्षा कम नहीं होती।

- **Chrome और Edge:** पैकेज अनज़िप करें और ब्राउज़र के एक्सटेंशन पेज पर **Load unpacked** इस्तेमाल करें।
- **Firefox:** Firefox पैकेज और `about:debugging` में **Load Temporary Add-on** इस्तेमाल करें। Firefox दोबारा शुरू होने पर अस्थायी एक्सटेंशन हट जाते हैं। इस रिलीज़ में स्टोर से साइन किया हुआ एक्सटेंशन उपलब्ध कराना शामिल नहीं है।
- **कुकी फ़ाइल:** विकल्प के तौर पर JSON और Netscape कुकी फ़ाइल इम्पोर्ट कर सकते हैं। फ़ाइल सीधे डैशबोर्ड में इम्पोर्ट करें; उसकी सामग्री AI बातचीत में पेस्ट न करें।

ब्राउज़र सत्र का डेटा सीधे स्थानीय क्रेडेंशियल वॉल्ट में भेजता है। मॉडल को खाते के लेबल, स्थानीय कुंजी के नाम और संरचना, तथा क्रेडेंशियल मान हटाए गए टूल नतीजे मिलते हैं। वे उन स्थानीय मानों का संदर्भ देने वाली कनेक्शन विधि बना सकते हैं, लेकिन मान स्वयं नहीं पाते। कुकी का दायरा, पाथ, समय सीमा और समर्थित पार्टिशन जानकारी लागू रहती है; प्रमाणीकरण हेडर अपने मूल ओरिजिन तक सीमित रहते हैं।

खाते की पहचान वेबसाइट से मिले मौजूदा खाते के असली जवाब से होती है। ब्राउज़र प्रोफ़ाइल का नाम वेबसाइट पर सत्यापित पहचान नहीं माना जाता। अगर खाते की पहचान अभी नहीं हुई है, तो Hycli यह बताता है। जुड़ने के बाद सामान्य ब्राउज़िंग से खाते का जवाब और उपलब्ध अनुरोधों की संरचना मिल सकती है। अनुरोधों के मान, हेडर या जवाब की सामग्री तैयारी करने वाले मॉडल को नहीं दिखाई जाती।

किसी वेबसाइट के लिए अलग, दस्तावेज़ों में बताई गई API क्रेडेंशियल या स्थानीय रूप से अनुपलब्ध ब्राउज़र क्षमता आवश्यक हो सकती है। तैयारी में वास्तविक कनेक्शन और पढ़ने के नतीजे दर्ज होते हैं। होमपेज मिलना या API से लॉगिन पेज लौटना, इंटीग्रेशन तैयार होने का प्रमाण नहीं है। [ब्राउज़र सेटअप गाइड](../../browser-companion/guide.html) कंपैनियन प्रक्रिया और सीमाएँ बताती है।

## भाषाएँ

डैशबोर्ड ऊपर दी गई 20 भाषाओं का समर्थन करता है, जिनमें दाएँ से बाएँ लिखी जाने वाली अरबी भी शामिल है। शुरुआती भाषा अंग्रेज़ी है। आपकी पसंद इस डिवाइस पर सहेजी जाती है और AI के विवरण चुनी गई भाषा में तैयार किए जा सकते हैं।

<a id="local-data"></a>
## स्थानीय डेटा और अनुरोध की सीमाएँ

वेबसाइट की परिभाषाएँ, खाते का मेटाडेटा और गतिविधि स्थानीय डेटा फ़ोल्डर में रहते हैं। दूसरा स्थान चुनने के लिए `HYCLI_DATA_DIR` सेट करें। मौजूदा स्थान और लॉगिन जानकारी की सुरक्षा **सेटिंग्स** में देखें।

उपलब्ध होने पर क्रेडेंशियल वॉल्ट ऐसी एन्क्रिप्शन कुंजी इस्तेमाल करता है जिसे ऑपरेटिंग सिस्टम का कीरिंग सुरक्षित रखता है। कीरिंग उपलब्ध न होने पर साफ़ बताया जाता है कि स्टोर की सुरक्षा सिर्फ़ फ़ाइल अनुमतियों पर आधारित है। निजी फ़ोल्डर और क्रेडेंशियल फ़ाइलें सिर्फ़ मौजूदा ऑपरेटिंग सिस्टम यूज़र के लिए खुली होती हैं। पहले से मौजूद एन्क्रिप्टेड वॉल्ट अनलॉक न होने पर चुपचाप बदला नहीं जाता।

हर वेबसाइट और खाते के अनुरोध क्रम से और तय अंतराल पर भेजे जाते हैं। पूरी वेबसाइट के लिए एक अतिरिक्त सीमा भी होती है। Hycli `Retry-After` का पालन करता है, जवाबों के आकार और पढ़ने की दोबारा कोशिशों को सीमित रखता है और लॉगिन विफल होने या वेबसाइट की अतिरिक्त जाँच आने पर रुकता है। वेबसाइट की तैयारी के दौरान Hycli खाते नहीं बदलता, डिजिटल फ़िंगरप्रिंट की नकल नहीं करता और जाँच को बायपास नहीं करता; इंजन का निदान संबंधी व्यवहार अलग हो सकता है। ये उपाय बेवजह का दबाव कम करते हैं; वे यह गारंटी नहीं देते कि वेबसाइट कभी खाते पर पाबंदी नहीं लगाएगी।

निजी और स्थानीय वेबसाइट के पते डिफ़ॉल्ट रूप से बंद हैं। अपनी होस्ट की हुई भरोसेमंद वेबसाइट के लिए डैशबोर्ड या MCP सर्वर को स्पष्ट रूप से `--allow-local` के साथ चलाएँ।

<a id="contributing"></a>
## डेवलपमेंट और जाँच

```sh
npm --prefix dashboard ci
npm --prefix dashboard run check
npm --prefix dashboard run build
cargo test --all-targets --locked
cargo build --locked --bin hycli --example dashboard_fixture
node scripts/test-e2e.mjs --full
```

टेस्ट नकली स्थानीय वेबसाइट और सेवा के जवाब इस्तेमाल करते हैं। वे मंज़ूरी को अनुरोध से बाँधने और दोबारा इस्तेमाल रोकने, गुप्त जानकारी हटाने, रीडायरेक्ट, अनुरोध की सीमाओं, बदलाव करने वाले अनुरोध दोबारा न चलाने, ब्राउज़र सत्र की सुरक्षा और सेवा के जवाबों के अपेक्षित प्रारूप की जाँच करते हैं। सिर्फ़ Hycli जाँचने के लिए किसी असली खाते में सामग्री कभी न बनाएँ, बदलें या मिटाएँ।

स्क्रीनशॉट और GIF में अलग रखे गए नमूना डेटा का उपयोग किया गया है। [चित्रों के स्रोत](../images/README.md) देखें।

## लाइसेंस और उपयोग का उद्देश्य

Hycli [Apache-2.0](../../LICENSE) लाइसेंस के तहत उपलब्ध है।

Hycli का उद्देश्य ऐसे कमांड-लाइन टूल बनाना और इस्तेमाल करना है जो वेबसाइटों का उपयोग आसान बनाएँ। इसे उन वेबसाइटों और खातों के साथ इस्तेमाल करें जिनका ऐक्सेस आपको अधिकृत रूप से मिला है।

यह सॉफ़्टवेयर जैसा है वैसा ही, बिना किसी वारंटी के दिया जाता है। कानून की अनुमति के दायरे में, इसके लेखक और योगदानकर्ता इसके उपयोग से होने वाले नुकसान या अन्य समस्याओं के लिए ज़िम्मेदार नहीं हैं। आप इसे कैसे इस्तेमाल करते हैं, इसकी ज़िम्मेदारी आपकी है।

कानून द्वारा अनुमत सीमा तक, Hycli के उपयोग के कारण खातों पर लगने वाले प्रतिबंध, निलंबन या सीमाओं के लिए लेखक और योगदानकर्ता उत्तरदायी नहीं हैं। हैकिंग, अनधिकृत पहुँच या हमलों के लिए Hycli का उपयोग न करें।
