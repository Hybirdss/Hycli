Hycli को किसी भी वेबसाइट का URL और अपना उद्देश्य बताएं। तीन AI वर्कर्स इसके डॉक्यूमेंटेशन, फ्रंटएंड JS बंडलों और वास्तविक ब्राउज़र नेटवर्क ट्रैफ़िक का विश्लेषण करके एक टाइप्ड CLI और MCP टूलसेट तैयार करते हैं — जिसमें पढ़ने (read) और लिखने (write) दोनों के कार्य शामिल होते हैं — और सेटअप के दौरान आपके खाते में कोई भी वास्तविक बदलाव नहीं किया जाता है।

<a id="try-it-in-30-seconds"></a>
## 30 सेकंड में आज़माएं

```sh
# 1. Hycli को किसी भी वेबसाइट का पता और अपना लक्ष्य दें (रीड और राइट तैयार करता है; सेटअप के दौरान शून्य लाइव बदलाव)
hycli prepare https://your-website.example --intent "पोस्ट खोजें, ड्राफ्ट सहेजें और लेख प्रकाशित करें"

# 2. तैयार किए गए सभी रीड, राइट और मल्टी-स्टेप वर्कफ़्लो देखें
hycli describe your-website

# 3. रीड और खोज कार्यों को तुरंत चलाएं
hycli your-website search-posts --query "रिलीज़ नोट्स"

# 4. जब आप कुछ बनाने, संपादित करने या हटाने के लिए तैयार हों, तो इस CLI के लिए एक बार राइट अनुमति चालू करें
hycli writes your-website allow
hycli your-website create-draft --title "Hycli से नमस्ते" --body "सीधे मेरे टर्मिनल से स्वचालित।"
```

या `"command": "hycli", "args": ["mcp"]` के साथ Hycli को एक बार **Claude Code, Cursor, Codex या Windsurf** से जोड़ें और अपने एजेंट से सामान्य भाषा में कहें:
> *"Hycli का उपयोग करके `https://...` तैयार करो, मुझे दिखाओ कि कौन-कौन से कार्य उपलब्ध हैं, और एक नई पोस्ट का ड्राफ्ट तैयार करो।"*

<a id="get-started"></a>
## शुरुआत करें

Hycli एक एकल नेटिव बाइनरी के रूप में आता है जिसमें वेबसाइट इंजन और स्थानीय डैशबोर्ड (`http://127.0.0.1:4318`) दोनों शामिल हैं। रिलीज़ पैकेज चलाने के लिए न तो Rust और न ही Node.js की आवश्यकता होती है।

### डाउनलोड करें और चलाएं (Windows, macOS, Linux)

अपने प्लेटफ़ॉर्म के लिए नेटिव इंस्टॉलर या पोर्टेबल आर्काइव **[GitHub Releases (v0.1.0)](https://github.com/Hybirdss/Hycli/releases/tag/v0.1.0)** से डाउनलोड करें:

| प्लेटफ़ॉर्म | आर्किटेक्चर | नेटिव इंस्टॉलर | पोर्टेबल आर्काइव | कैसे शुरू करें |
| --- | --- | --- | --- | --- |
| **Windows 10/11** | x64 और ARM64 | `hycli-0.1.0-win32-*-setup.exe` | `hycli-0.1.0-win32-*.tar.gz` | `*-setup.exe` चलाएं (यह उपयोगकर्ता के `PATH` और स्टार्ट मेनू में `hycli` जोड़ता है), फिर **Hycli** खोलें या PowerShell में `hycli open` चलाएं। |
| **macOS 13+** | Apple Silicon (`arm64`) और Intel (`x64`) | `hycli-0.1.0-darwin-*.dmg` | `hycli-0.1.0-darwin-*.tar.gz` | `.dmg` खोलें, **Hycli.app** को **Applications** में ड्रैग करें और खोलें (यह स्वतः `~/.local/bin` में `hycli` को लिंक कर देता है)। |
| **Linux** | x64 और ARM64 | `hycli-0.1.0-linux-*.deb` | `hycli-0.1.0-linux-*.tar.gz` | `.deb` इंस्टॉल करें (`sudo apt install ./hycli-*.deb`) या `.tar.gz` एक्सट्रैक्ट करके `./install.sh` चलाएं, फिर `hycli open` चलाएं। |

### अपनी पहली वेबसाइट जोड़ें

1. `http://127.0.0.1:4318` पर स्थानीय डैशबोर्ड खोलने के लिए `hycli open` चलाएं (या **Hycli** ऐप आइकन पर क्लिक करें)।
2. **AI कनेक्शन** खोलें और OpenAI, Anthropic Claude, xAI, Z.ai या अपने स्थानीय ChatGPT (Codex) लॉगिन को कनेक्ट करें।
3. जिन साइटों के लिए लॉगिन आवश्यक है, वहां अपने ब्राउज़र सत्र को स्थानीय एन्क्रिप्टेड वॉल्ट में आयात करने के लिए **खाते → मेरा साइन-इन खोजें** पर क्लिक करें।
4. वेबसाइट URL और वैकल्पिक लक्ष्य दर्ज करें, या **कोडिंग एजेंट** से MCP कॉन्फ़िगरेशन कॉपी करके अपने AI सहायक में पेस्ट करें।

<a id="what-your-ai-can-do"></a>
## आपका AI क्या कर सकता है

Hycli वास्तविक वेबसाइट इंटरफ़ेस को स्व-प्रलेखित (self-documented) CLI सबकमांड और MCP टूल्स में बदल देता है:

| वेबसाइट इंटरफ़ेस | तैयार की गई क्षमता |
| --- | --- |
| REST और OpenAPI | JSON/YAML स्कीमा और API डॉक्स पर आधारित टाइप्ड रीड और राइट कार्य। |
| GraphQL | टाइप्ड JSON वेरिएबल्स के साथ पार्स किए गए क्वेरी (`query`) और म्यूटेशन (`mutation`) दस्तावेज़। |
| HTML और JS-रेंडर्ड पेज | स्थानीय Chromium इंजन के माध्यम से संरचित रिकॉर्ड, लिंक, पेजिनेशन और रेंडर किए गए GET रीड्स। |
| JSON और URL-एनकोडेड फ़ॉर्म | प्रलेखित इनपुट, डिफ़ॉल्ट मान और खाता-आधारित फ़ॉर्म सबमिशन (`POST`, `PUT`, `PATCH`, `DELETE`)। |

| कार्य का प्रकार | निष्पादन व्यवहार |
| --- | --- |
| **पढ़ना या खोजना (Read / Search)** | साक्ष्य द्वारा प्रमाणित होने और सुरक्षित रीड के रूप में वर्गीकृत होने पर तुरंत चलता है। |
| **बनाना, भेजना, संपादित करना या हटाना (Write)** | तैयारी के दौरान कभी भी चलाए बिना खोजा जाता है और CLI स्पेक में जोड़ा जाता है। डिफ़ॉल्ट रूप से बंद (`writes: false`) रहता है। आपका AI एजेंट राइट कार्यों को चालू करने के लिए **प्रति CLI एक बार** आपसे पूछता है (`hycli writes SITE allow` या MCP `hycli_writes`)। एक बार अनुमति मिलने के बाद, आपके कहने पर राइट कार्य सीधे चलते हैं। |
| **अस्पष्ट प्रभाव** | भेजने से पहले समीक्षा के लिए रोका जाता है। |
| **प्रमाणीकरण चुनौती या दर सीमा (Rate limit)** | ट्रांसपोर्ट रणनीति बदलता है (HTTP → पेज के भीतर `window.fetch` → स्टेल्थ Chromium) या सुरक्षित रूप से रुक जाता है। |

समर्थित अनुरोध प्रारूपों और डेटा निष्कर्षण नियमों के लिए [ऑपरेशन संदर्भ](../SITESPEC.md) देखें।

<a id="common-concerns"></a>
## आम चिंताएं और Hycli उन्हें कैसे हल करता है

किसी AI एजेंट को वास्तविक वेबसाइटों और लॉग-इन किए गए खातों से जोड़ने पर गंभीर सवाल उठते हैं। यहां बताया गया है कि Hycli डिज़ाइन के स्तर पर प्रत्येक का समाधान कैसे करता है:

### 1. "क्या AI गलती से मेरे खाते पर डेटा पोस्ट, संपादित या डिलीट कर देगा?"
- **CLI निर्माण के दौरान शून्य लाइव बदलाव:** किसी वेबसाइट को तैयार या चेक करते समय (`hycli prepare`, `hycli request`, `hycli recon`, `hycli check`), Hycli रीड और राइट दोनों ऑपरेशनों को खोजकर CLI स्पेक में संकलित करता है, लेकिन **कभी भी राइट अनुरोध निष्पादित नहीं करता है**। यहां तक कि छुपे हुए बदलाव (`/delete` जैसे पाथ वाले `GET` रूट, GraphQL `mutation` बॉडी, या HTML `<form method="post">` एक्शन) भी सत्यापन के दौरान चलने से रोक दिए जाते हैं।
- **प्रति-CLI एक बार राइट की पुष्टि:** हर नया बना वेबसाइट CLI `writes: false` के साथ शुरू होता है। जब किसी AI एजेंट को किसी CLI पर पहली बार राइट कार्य चलाने की आवश्यकता होती है, तो वह **उस CLI के लिए एक बार** आपसे पूछता है: *"क्या `<site>` के लिए राइट कार्यों की अनुमति दें?"* आपके द्वारा पुष्टि किए जाने के बाद ही वह `hycli writes <site> allow` (या MCP `hycli_writes`) चलाता है, जिससे उस CLI के लिए सीधा राइट निष्पादन सक्रिय होता है। आप किसी भी समय `hycli writes <site> deny` या डैशबोर्ड के **बदलावों की अनुमति दें** टॉगल से अनुमति वापस ले सकते हैं।
- **असफल राइट्स का कोई स्वचालित रीट्राई नहीं:** विफल या बाधित राइट अनुरोधों को कभी भी अपने आप दोबारा नहीं चलाया जाता है। यदि बदलाव भेजने के बाद कनेक्शन टूट जाता है, तो Hycli डुप्लिकेट ऑर्डर या पोस्ट करने के बजाय `action_outcome_unknown` की रिपोर्ट देता है ताकि आप पहले वेबसाइट की जांच कर सकें।

### 2. "क्या Hycli मेरी कुकीज़, लॉगिन टोकन या API कुंजियां AI मॉडल को भेजता है?"
- **सीक्रेट्स कभी भी LLM प्रॉम्प्ट्स में नहीं जाते:** ब्राउज़र कुकीज़, `localStorage` / `sessionStorage` टोकन और API कुंजियां सख्ती से आपके स्थानीय वॉल्ट में संग्रहीत होती हैं (Windows क्रेडेंशियल मैनेजर, macOS कीचेन और Linux Secret Service पर OS कीरिंग द्वारा एन्क्रिप्टेड, या केवल उपयोगकर्ता के लिए `0600` अनुमतियों तक सीमित)।
- **सिंबॉलिक कनेक्शन रेसिपी (`ConnectionRecipe`):** AI मॉडल केवल खाता लेबल, स्टोरेज कुंजी के नाम और मास्क किए गए रिस्पॉन्स स्कीमा देखते हैं। मॉडल एक सिंबॉलिक `ConnectionRecipe` (केवल कुकी या टोकन नाम का संदर्भ देते हुए) बनाता है, और Hycli निष्पादन के समय वास्तविक सीक्रेट को स्थानीय रूप से इंजेक्ट करता है तथा सभी आउटपुट और लॉग से सीक्रेट्स को हटा देता है।
- **साइट-सीमित रीड-ओनली आयात:** ब्राउज़र सत्र आयात करने पर अस्थायी रीड-ओनली स्नैपशॉट से केवल लक्षित डोमेन की कुकीज़ और स्टोरेज पढ़े जाते हैं। यह कभी भी ब्राउज़र सुरक्षा को कमजोर नहीं करता और न ही अन्य वेबसाइटों का डेटा निर्यात करता है।

### 3. "क्या स्क्रैपिंग से CAPTCHA आएगा या मेरा खाता प्रतिबंधित (ban) हो जाएगा?"
- **कोई फ़ज़िंग या ब्रूट-फ़ोर्स स्कैनिंग नहीं:** Hycli कभी भी एंडपॉइंट वर्डलिस्ट का अनुमान नहीं लगाता और न ही लाइव सर्वरों पर फ़ज़िंग करता है। यह केवल लिंक किए गए डॉक्यूमेंटेशन, OpenAPI/GraphQL स्कीमा, स्टैटिक JS बंडलों और देखे गए ब्राउज़र नेटवर्क आकारों से सीखता है।
- **क्रमबद्ध और गति-नियंत्रित ट्रैफ़िक:** अनुरोधों को प्रत्येक वेबसाइट और प्रत्येक खाते के अनुसार क्रमबद्ध और गति-सीमित (rate-limited) किया जाता है, `Retry-After` का पालन किया जाता है और रीड रीट्राई को सीमित रखा जाता है।
- **रणनीति सर्किट ब्रेकर और वास्तविक ब्राउज़र निष्पादन:** जब सामान्य HTTP अनुरोध 403/429 या बॉट चुनौती (Cloudflare, Akamai Bot Manager) से टकराता है, तो Hycli अवरुद्ध अनुरोध को बार-बार लूप में नहीं चलाता। इसका सर्किट ब्रेकर तुरंत ट्रांसपोर्ट बदल देता है — आपके प्रमाणित ब्राउज़र संदर्भ के भीतर `window.fetch(..., { credentials: 'include' })` चलाकर या स्थानीय स्टेल्थ Chromium इंजन का उपयोग करके — अथवा आपके खाते की सुरक्षा के लिए साफ तौर पर रुक जाता है।

### 4. "क्या कोई रीडायरेक्ट मेरे सत्र को लीक कर सकता है, या साझा किया गया स्पेक मेरे कंप्यूटर के पाथ उजागर कर सकता है?"
- **सख्त ओरिजिन बाइंडिंग (Origin binding):** प्रमाणीकरण हेडर और कुकीज़ लक्षित ओरिजिन से बंधे होते हैं और क्रॉस-ओरिजिन रीडायरेक्ट पर तुरंत हटा दिए जाते हैं। जब तक `--allow-local` स्पष्ट रूप से पास न किया जाए, निजी और लूपबैक IP रेंज डिफ़ॉल्ट रूप से अवरुद्ध रहते हैं।
- **पोर्टेबल स्पेक्स:** स्थानीय ब्राउज़र निष्पादन योग्य फ़ाइल और प्रोफ़ाइल पाथ केवल मशीन-लोकल स्थिति में रहते हैं और कभी भी पोर्टेबल `SiteSpec` फ़ाइलों में नहीं लिखे जाते हैं।

### 5. "जब मेरा लॉगिन समाप्त हो जाएगा, तो क्या AI बार-बार प्रयास करके टोकन बर्बाद करेगा?"
- **AI के बिना निश्चित स्वास्थ्य जांच (`hycli check`):** `hycli check` (और MCP `hycli_check`) बिना किसी LLM को कॉल किए सत्यापित रीड चेन को फिर से चलाता है और `signed_out` (अपना खाता फिर से जोड़ें) को `site_changed` (स्पेक की मरम्मत करें), `blocked` और `unreachable` से स्पष्ट रूप से अलग करता है।

<a id="use-hycli-with-your-ai"></a>
## अपने AI के साथ Hycli का उपयोग करें

अपने MCP क्लाइंट में Hycli जोड़ें (**कोडिंग एजेंट → कनेक्शन सेटिंग्स देखें** आपके OS के लिए सटीक पाथ दिखाता है):

```json
{
  "mcpServers": {
    "hycli": {
      "command": "hycli",
      "args": ["mcp"]
    }
  }
}
```

केवल इंस्टॉल किए गए वेबसाइट टूल्स को दिखाने के लिए `hycli mcp --sites-only` का उपयोग करें, या किसी एक साइट तक सीमित करने के लिए `--only-site SITE` जोड़ें। MCP सर्वर `hycli_prepare`, `hycli_writes` (आपसे पूछने के बाद प्रति CLI एक बार राइट्स सक्षम करता है), `hycli_run`, `hycli_check`, `hycli_result` और `hycli_activity` प्रदान करता है — और क्रेडेंशियल्स पढ़ने के लिए कभी भी कोई टूल उजागर नहीं करता है।

टर्मिनल से भी हर वर्कफ़्लो बिल्कुल उसी तरह काम करता है:

```sh
hycli prepare https://your-website.example --intent "सहेजे गए संदर्भ खोजें"
hycli request SITE "पूरी पोस्ट सामग्री के साथ ड्राफ्ट संपादन और प्रकाशन जोड़ें"
hycli describe SITE
hycli SITE ACTION --help
hycli writes SITE allow
hycli SITE ACTION --query "design systems"
hycli check SITE
```

<a id="browser-sign-in"></a>
## ब्राउज़र साइन-इन

Hycli Windows, macOS और Linux पर स्थानीय Chrome, Chromium, Edge, Brave, Vivaldi, Arc, Whale और Firefox प्रोफ़ाइलों (तथा इंस्टॉल होने पर स्थानीय स्टेल्थ Chromium बाइनरी) को खोजता है, और केवल अनुरोधित वेबसाइट के सत्र को स्थानीय वॉल्ट में आयात करता है। एक ही सत्यापित वेबसाइट खाते को साझा करने वाली प्रोफ़ाइलें स्वचालित रूप से एक कर दी जाती हैं।

यदि कोई सत्र Windows App-Bound एन्क्रिप्शन, निजी कंटेनरों या किसी अपंजीकृत ब्राउज़र द्वारा लॉक किया गया है, तो अपने ब्राउज़र के माध्यम से साइन इन करने के लिए **खाते → खाता जोड़ें** का उपयोग करें, [ब्राउज़र कंपैनियन एक्सटेंशन](../../browser-companion/guide.html) कनेक्ट करें, या डैशबोर्ड में JSON/Netscape कुकी फ़ाइल आयात करें (कभी भी AI चैट में कुकीज़ पेस्ट न करें)।

## स्थानीय डेटा और अनुरोध सीमाएं

वेबसाइट परिभाषाएं, एन्क्रिप्टेड क्रेडेंशियल और गतिविधि लॉग आपके OS डेटा डायरेक्टरी (Windows पर `%LOCALAPPDATA%\hycli`, macOS पर `~/Library/Application Support/hycli`, Linux पर `~/.local/share/hycli` या `HYCLI_DATA_DIR`) में रहते हैं। **सेटिंग्स** के अंतर्गत किसी भी समय सक्रिय वॉल्ट सुरक्षा की जांच करें।
